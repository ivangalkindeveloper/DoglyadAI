# Проверка инструкций без обрезания ответа

Дата: 4 ноября 2026 года. Все входные данные синтетические. Результаты не
подтверждают клиническую пригодность модели.

Выполнено **120 диагностических генераций** без учёта разогрева.
**Надёжное исправление не подтверждено.** Короткая инструкция устраняет повторы
на этом наборе, но подавляет полезные замечания. Она отклонена.

В рабочем коде удалены `maxLength` и соответствующие настройки длины четырёх
текстовых разделов. Удалены указания этих ограничений в инструкциях. Прежняя
подробная инструкция и `repetition_penalty=1.05` сохранены. JSON Schema,
проверка повторов, лимит токенов и App Check сохранены. Изменений движков и
перезапусков контейнеров не было.

Ещё 60 запросов относятся к первичному поиску вариантов. Они перечислены ниже

Во всех **26** запросах короткой инструкции через main замечания равны `null`.
Среди них **девять запросов с противоречием**: четыре версии описания щитовидной
железы и один конфликт мочевого пузыря у 4B, ещё по два конфликта у остальных
моделей. Поэтому ноль циклов не считается выполнением всей задачи.
В прежней инструкции замечание к конфликту мочевого пузыря хотя бы приводило
два несовместимых утверждения; короткая инструкция убрала и его.

В контрольных ответах сохранённой конфигурации цикл не возник, но 4B заменила
«соответствует верхней границе нормы» на «превышает верхнюю границу нормы».
В конфликтном примере замечание спрашивает размер образования вместо
указания противоречия. Проверка main принимает эти ответы: она проверяет
структуру, измерения и повторы, но не всю семантику. Два контрольных запуска
не доказывают устранение циклов.

Набор выявил и другие ограничения: ошибка «анофагенное» не исправлена,
явное исправление врача может сохраниться вместе с устаревшим отрицанием,
27B в одном ответе вернула строку `"null"` вместо значения `null` в рекомендациях.
Эти факты записаны как ошибки качества; подмена или удаление строк их не исправляет.

Медиана времени полного ответа при парном сравнении составила 15.04 с
для прежней инструкции и 6.38 с для короткой. У короткой версии меньше текста
и нет длинных циклов. Это не ускорение вычисления одного токена и не основание
принимать вариант, потерявший замечания.

## Цель и условия

Устранить повторение в конце протокола, сохранив structured output. Лимит
`maxLength` не считается исправлением: грамматика может закрыть строку посреди
слова. Во всех новых опытах нет `maxLength` и используется
`repetition_penalty=1.0`. Общий бюджет — 2048 токенов.

Использован действующий vLLM на DGX Spark, BF16, XGrammar с
`disable_any_whitespace=true`. Контейнеры не пересоздаются. Проверки идут
последовательно, при штатном `max-num-seqs=4`. Это не испытание нагрузки.

Проба обращается к приватному движку внутри его контейнера. Она сохраняет сырой
SSE-ответ до остановки движка, включая ошибочные повторы. Защита main не прерывает
эти диагностические запросы. Затем ответы проходят проверку main отдельно.
App Check и рабочие HTTP-маршруты не изменены. Полный сетевой путь iOS → main →
inference этой пробой не проверяется.

## Что сравнивается

- `screening-*`: исходная инструкция без ограничения длины; удаление словаря;
  короткие русская и английская инструкции. По четыре запроса на вариант.
- `examples-*`: примеры ответов, порядок полей и их комбинации. По четыре запроса.
- `audit-*`: структурированный вход и отдельная проверка исходного текста.
  Последняя возвращает замечание либо пары номеров противоречащих предложений.
- `placement-*`: задание после данных, отдельный аудит с таким же порядком,
  переименование полей. По четыре запроса на вариант.
- `expanded-*`: парное сравнение прежней и короткой инструкции на 16 запросах.
  Меняется только системная инструкция. Вход, схема, seed, температура и движок
  совпадают. Набор включает исходное описание щитовидной железы, конфликтный
  вариант, исследования мочевого пузыря и почек, явное исправление врача,
  продиктованное заключение, ошибку распознавания термина, шаблон и английский ввод.
- `actual-*`: запросы собирает `ReportGenerationService.prepare` изменённого
  backend-кандидата. Текст инструкции вручную не заменяется. Для 4B используется весь
  расширенный набор; для 1.5 4B и 27B — по пять контрольных запросов.

Восемь исходных запросов — два описания, каждое при temperature=0/seed=0 и
при temperature=0.3/seeds=0,42,123. Восемь дополнительных описаний проверяются
при temperature=0.3/seed=42. Это небольшой целевой набор, а не независимая
оценка частоты ошибок на всех исследованиях.

## Наблюдения

В исходном варианте модель переносит слова из `contextualStrings` в требования
уточнить источник. Например, после корректного описания мочевого пузыря она
последовательно спрашивает, является ли находка тенью, утолщением, жидкостью,
мочеточником и другими терминами, затем повторяет цепочку. Словарь не содержит
таких данных пациента.

Таким образом, повтор существует в сыром ответе движка. SSE и клиент его не
создают. Валидная JSON Schema ограничивает структуру, но не запрещает повторять
содержимое строки. Результат сравнения инструкций не доказывает, что длина
инструкции сама по себе является единственной причиной: меняются также её
формулировки и порядок указаний.

Отдельный аудит пока не стал решением. Он копирует исходные фразы или возвращает
пустой список конфликтов. Английская инструкция, примеры, перестановка полей и
переименование полей не дали надёжной проверки противоречий. Эти изменения не
перенесены в API. Подробные замечания: `review_notes.json`.

## Файлы и воспроизведение

`*-cases.json` — замороженные тела запросов и схемы. `*-results.jsonl` — сырые
ответы, причины остановки, число токенов, длительность и идентификаторы токенов.
`*-validation.json` и `summary.json` — техническая проверка ответов. Значение
`main_valid` не означает медицинскую достоверность. Для отдельного аудита
проверка полноценного протокола неприменима; см. поле `task`.

`*-runtime-before.json`, `*-runtime-after.json`, `*-other-activity.json` и логи
контроллеров проверяют неизменность контейнеров, их готовность и отсутствие
генерации на остальных движках. Разогрев отмечен отдельно и исключён из итогов.
`actual-source.json` содержит хеши отклонённого кандидата;
`final-source.json` — сохранённой конфигурации для `final-smoke`.
`candidate-catalog.json` хранит предложенные тексты, а `pre-candidate-catalog.json`
содержит прежние тексты после удаления ограничений длины. Подготовительные скрипты используют код своего момента запуска;
для точного повтора нужно брать замороженные запросы.

`run_experiment.py <manifest.json> [имя контейнера]` запускается на DGX рядом
с сохранёнными `schema-revision/probe_engine.py` и его зависимостями. Существующие
результаты намеренно не перезаписываются. Повторный запуск требует нового имени
варианта и manifest. Проверка локально:

```bash
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-03/prompt-repair/analyze_experiment.py
```

## Изменения и проверка кода

Удалены четыре `max_*_characters` из `USReportGenerationConfig` и обоих
`server.json`. Сборщик схемы больше не вставляет `maxLength`. `PromptFactory`
не подставляет лимит в текст инструкции. `ReportValidator` сохраняет проверку
повторов, но не отклоняет корректный ответ только за достижение длины строки.

Регрессионный тест проверяет сохранение русского замечания длиннее 512 символов
в частичном и готовом ответах. В тестах прерывания потока пример с разными
номерами групп заменён реальным повтором из эксперимента: прежний пример
отклонялся из-за длины, а не из-за точного повторения. Проверки закрытия upstream,
сохранения незавершённого снимка и освобождения резерва остаются.

Проверки main: **587 passed, 5 skipped**; Ruff, mypy (279 файлов), форматирование
прошли. Полная проверка архитектуры сообщает 13 прежних нарушений
`swift.view-fragment` в iOS-файлах, не изменённых в этом эксперименте.

## Решение

Короткий промпт, перестановка полей, отдельный аудит и переименование полей
не приняты. Ограничение длины не используется как лечение зацикливания.
Сохранение structured output остаётся совместимым с задачей, но валидный JSON
не гарантирует соблюдение инструкции и сохранение смысла.

Следующий этап требует отдельного критерия качества для замечаний: правильное
указание обеих конфликтующих фраз, отсутствие замечания на явное исправление,
сохранение исходных фактов и отсутствие циклов. Для выбора другой модели или
дообучения нужно оценивать эти критерии вместе. Результат текущего эксперимента
не даёт оснований автоматически заменить модель или объявить её исправленной.
