# Завершение генерации после проверки JSON

## Результат

В inference-сервис добавлен `StructuredOutputReader`. Он определяет конец
корневого JSON-объекта, массива или строки и проверяет результат по переданной
JSON Schema. После успешной проверки сервис закрывает поток vLLM и освобождает
место в очереди. Последний фрагмент передаётся клиенту после освобождения ресурсов.

Обе ручки используют этот механизм: `/v1/generation` собирает полный ответ,
`/v1/generation/stream` передаёт фрагменты. Медицинская проверка результата
остаётся в main backend. Завершённый JSON сам по себе не доказывает правильность
содержания.

Установлен на DGX локальный ARM64-образ:
`sha256:a792e0ead52145ea6860d962b37c194eb30da00a22cd127df4c20193d84129c9`.
Сборка основана на ранее установленном образе с обновлением исходников inference
и зависимостей проверки JSON Schema. Публикация в GHCR и fleet rollout не выполнялись.

## Границы обработки

- Вложенные объекты, массивы, кавычки и экранирование учитываются между фрагментами.
- Синтаксические ошибки, повторные ключи и несоответствие схеме отклоняются.
- Локальные `$ref` поддерживаются. Внешние схемы по сети не загружаются.
- После закрытого корня допускаются только JSON-пробелы в том же фрагменте.
- Числа и другие корневые значения без ограничителей ждут обычного завершения
  vLLM. Например, фрагмент `1` может продолжиться до `12`.
- Обычный текст также требует `finish_reason=stop` и `[DONE]`.
- Если модель повторяет текст внутри незакрытой строки или пробелы между
  незавершёнными полями, этот механизм не объявляет ответ готовым.

## Локальные проверки

- Pytest inference: 103 теста прошли.
- Mypy: ошибок нет в 56 исходных файлах.
- Ruff и форматирование Python: прошли; 0 из 68 файлов требуют форматирования.
- Проверка архитектуры изменённых файлов inference: прошла.
- Тесты профиля развёртывания: 9 прошли.

Тесты проверяют досрочное закрытие HTTP-потока, освобождение очереди до последнего
`yield`, остановку без `[DONE]`, отклонение неверного JSON и работу обеих ручек.
Проверки выполнялись с синтетическими данными.

## Проверка ранней остановки на DGX

В двух запросах к 4B принудительно задано `min_tokens=512`. Схема требует только
`{"ok":true}`. Разрешённые пробелы позволяют модели продолжать генерацию после
закрытия объекта. Обновлённый reader вернул готовый объект раньше обычной остановки:

| Метод сервиса | Время, с | Активные запросы vLLM после закрытия |
|---|---:|---:|
| `generate` | 0.907 | 0 |
| `stream` | 0.226 | 0 |

Артефакты: `completion-cases.json`, `completion-live-results.jsonl`,
`run_completion_checks.py`, `whitespace_transport.py`.

До установки образ также прошёл шесть коротких проверок в текущем компактном
формате: оба метода на каждой из трёх моделей. Все ответы прошли JSON Schema;
после каждого запроса счётчики выполняемых и ожидающих запросов vLLM равны нулю.
Артефакт: `completion-image-preflight.jsonl`.

## Полные примеры в установленном сервисе

После установки выполнены шесть последовательных запросов через `VLLMService`
в рабочем контейнере с текущей компактной грамматикой. Протоколы получены через
`stream`, диктовки — через `generate`. Использованы те же синтетические примеры
и нейтральный `repetitionPenalty=1.0` из эксперимента, без изменения рабочих
параметров main.

| Модель | Протокол: JSON Schema / main | Диктовка: JSON Schema / main |
|---|---|---|
| MedGemma 4B | Прошла / повторения, `invalidReportResponse` | Прошла / прошла |
| MedGemma 1.5 4B | Прошла / прошла | Прошла / прошла |
| MedGemma 27B | Прошла / прошла | Прошла / прошла |

Время запросов: 4B — 27.701 / 22.950 с; 1.5 4B — 15.801 / 28.092 с;
27B — 83.107 / 37.466 с. Порядок: протокол / диктовка. Это единичные проверки
работоспособности, не сравнение производительности. После каждого запроса
активные и ожидающие запросы vLLM отсутствовали.

В протоколе 4B JSON завершён, но некоторые предложения в описании повторены
трижды. Отдельный вызов проверки повторов подтверждает `invalidReportResponse`.
Сервис правильно завершает JSON, а main отклоняет неприемлемое содержание.
Успех ранней остановки нельзя считать устранением повторов.

Артефакты: `completion-deployed-native.jsonl`,
`completion-deployed-main-validation.json`, `run_image_completion_checks.py`,
`validate_completion_results.py`. Исходники 56 файлов `app` в установленном
контейнере побайтово совпадают с локальными.

## Почему свободное форматирование не включено глобально

Отдельно проверены текущие синтетические промпты протокола и диктовки с грамматикой,
которая разрешает свободные пробелы. В этой проверке нейтральный
`repetitionPenalty=1.0`; рабочие значения параметров не изменялись.

| Модель | Протокол | Диктовка |
|---|---|---|
| MedGemma 4B | JSON и проверка main прошли | Незавершённый JSON |
| MedGemma 1.5 4B | Незавершённый JSON | Тайм-аут |
| MedGemma 27B | Тайм-аут | JSON и проверка main прошли |

Во время части проверок выполнялась другая диагностика на том же GPU.
Эти времена не являются бенчмарком. Тайм-аут сам по себе не устанавливает
причину сбоя и не доказывает регрессию нового reader.

В парном сравнении диктовки 4B найден конкретный сбой свободного форматирования:
модель повторяет пустые строки внутри объекта до закрытия корня. Она достигает
2048 токенов с `finish_reason=length`. Компактный вариант того же запроса
завершается за 567 токенов и возвращает JSON. Артефакт:
`voice-grammar-comparison.jsonl`. Распознавание закрытого JSON не устраняет
такой цикл, поскольку JSON ещё не закрыт.

Поэтому `disable_any_whitespace=true` сохранён. Форматирование, веса,
квантование и рабочие параметры генерации этим обновлением не меняются.
Вывод прежнего исследования о влиянии компактного контекста на повторение
строк остаётся в [основном отчёте](README.md). Полное устранение повторов
новым reader не подтверждено.

В историческом `completion-live-results.jsonl` поле `valid_json` у успешной
диктовки 27B ошибочно равно `false`: скрипт проверял тип `dict`, хотя диктовка
возвращает массив. Ответ разобран и прошёл проверку main. Скрипт исправлен;
исходный артефакт сохранён. Подробности проверки main:
`completion-main-validation.json`.

## Установка и восстановление

Цель: inference-сервис DGX `192.168.0.29`. Обновлён только `backend_inference`
через существующий `start.py`, без флага `--restart`. ID и время старта трёх
vLLM-контейнеров до и после обновления совпадают. Compose, профиль хоста и
лимиты сервиса сохранены. Это относится к данному обновлению; в предыдущем
исследовании 4B временно останавливался для проверки Transformers.

Обе HTTP-ручки без токена возвращают 401. Эта проверка подтверждает доступность
и защиту App Check, но не проверяет полный путь iOS → main → inference.
Проверка с Mac через `127.0.0.1:18100` также вернула 401: туннель доступен.
Функциональные проверки вызывают `VLLMService` из образа по приватной Docker-сети;
защита HTTP-ручек не отключалась.

Предыдущий образ сохранён:
