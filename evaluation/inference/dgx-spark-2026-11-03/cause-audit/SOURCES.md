# Источники исследования 4 ноября 2026 года

Ни один внешний отчёт сам по себе не доказывает причину в Doglyad.
Ниже отделены результаты авторов от их применимости к нашим измерениям.

| Источник | Что установлено или предложено | Применимость |
|---|---|---|
| [Google: MedGemma 1 model card](https://developers.google.com/health-ai-developer-foundations/medgemma/model-card-v1) | Google отмечает повышенную чувствительность MedGemma к конкретной инструкции относительно Gemma 3. Исправление июля 2025 касается токена конца изображения; текстовый режим им не затронут. | Чувствительность согласуется с нашими парными опытами. Ошибка изображения не объясняет текстовые запросы без фотографий. Англоязычная safety-оценка не означает, что русский официально запрещён. |
| [MedGemma 1.5: guided JSON, форум Google](https://discuss.ai.google.dev/t/medgemma-1-5-4b-on-vllm-with-guided-json-output-pads-with-whitespace-until-max-new-tokens-instead-of-finishing/186784) | Автор на BF16 описывает пробельный цикл; после запрета свободного whitespace получает повторение выдуманного текста внутри строки. `maxLength` закрывает JSON, но оставляет неверное содержимое. | Близкий симптом. У нас запрет whitespace уже действует. Предложенный в комментарии stop ID107 применять нельзя: в установленном токенизаторе это перевод строки, а конец хода — 106. |
| [Google-Health/medgemma #40](https://github.com/Google-Health/medgemma/issues/40) | Участник Google связывает повторы 27B-text при function calling с отсутствием оптимизации для этой задачи и рекомендует базовую Gemma для вызова функций. | У нас медицинский отчёт, а не function calling. Нельзя делать вывод, что MedGemma вообще не поддерживает JSON. Готового исправления нашей генерации issue не содержит. |
| [Google-Health/medgemma #57](https://github.com/Google-Health/medgemma/issues/57) | В обсуждении длинного китайского входа воспроизведён повторяющийся текст; предложены greedy, repetition penalty=1.3 и no_repeat_ngram_size=4. | Этот рецепт уже испытан в `deep-investigation/`. Он не подтвердил сохранение качества. Закрытие issue по неактивности не является исправлением модели. |
| [TEMPLAR, приложение C.6.4](https://arxiv.org/html/2610.05247v1#A3.SS6.SSS4) | В исследовании медицинских шаблонов MedGemma-27B-IT повторила одно значение 1714 раз. Авторы различают деградацию генерации и последующую ошибку парсинга. | Независимый медицинский пример того же класса. Их восстановление и удаление дубликатов допустимы для множеств значений шаблона; это не доказанное исправление свободного текста нашего протокола. |
| [Learning to Break the Loop, NeurIPS 2022](https://arxiv.org/abs/2206.02369) | Авторы измеряют рост вероятности повторения при увеличении числа копий предложения. Предлагают обучение DITTO против повторов. | Наш опыт с копиями измеряет тот же тип эффекта на MedGemma. DITTO не устанавливался и не проверялся. Это изменение обучения модели, а не готовая настройка vLLM. |
| [Grammar-Aligned Decoding](https://arxiv.org/abs/2405.21047) | Авторы показывают, что локальное ограничение токенов грамматикой может менять распределение полных ответов и ухудшать содержание. Предложен ASAp. | Объясняет, почему валидная грамматика не обеспечивает качество. Не подтверждает дефект нашего XGrammar. ASAp в этой серии не внедрялся. |
| [Ollama #15502](https://github.com/ollama/ollama/issues/15502) | Gemma 4 повторяет текст в длинных JSON-строках. Включение схемы в prompt улучшает простой пример, но в последующих сложных случаях повторы сохраняются. | Другие модель и движок. У нас схема уже включена в prompt. Это не отсутствующая инструкция формата. |
| [Gemma #622](https://github.com/google-deepmind/gemma/issues/622) | Авторы сообщают о циклах Gemma 4 при constrained JSON в разных средах. | Не доказывает тот же механизм у Gemma 3 / MedGemma. Версии о квантизации и SSE нужно проверять отдельно; наши BF16 и парные stream/non-stream проверки их не подтвердили. |
| [vLLM #54881](https://github.com/vllm-project/vllm/issues/54881), [исправление #52830](https://github.com/vllm-project/vllm/pull/52830) | Исправлена передача reasoning-настроек при общем движке парсеров reasoning/tool calling. Автор подтверждает исправление в более позднем build. | В нашей MedGemma нет этих reasoning/tool-парсеров. Обновление vLLM ради этого PR не является обоснованным исправлением нашего цикла. |
| [vLLM #53717](https://github.com/vllm-project/vllm/issues/53717) | Сообщение о повторении переводов строки MedGemma 27B. | Другой вид повторов. Сам issue не содержит доказательства причины наших повторяющихся предложений. Полные пользовательские metadata из issue не сохранялись. |
| [MLX-VLM #1254](https://github.com/Blaizzy/mlx-vlm/issues/1254) | Повторы могут возникать при использовании сырого prompt без применения chat template. | Родной template в наших запросах проверен по точным token IDs. Этот путь исключён для исследованных запросов. |
| [Эксперимент автора coles.codes](https://coles.codes/posts/grammar-constrained-repetition-trap/) | В его проверках Qwen3-VL и Gemma с JSON встречались повторы. Сильный penalty давал валидный, но пустой результат. | Это первичный отчёт автора о своих измерениях, но с небольшими наборами и другими моделями. Поддерживает требование проверять содержание отдельно; его выводы о выборе hosted-модели на Doglyad не переносятся. |
| [vLLM: structured outputs](https://docs.vllm.ai/en/latest/features/structured_outputs/), [XGrammar matcher](https://github.com/mlc-ai/xgrammar/blob/main/python/xgrammar/matcher.py), [Gemma prompt structure](https://ai.google.dev/gemma/docs/core/prompt-structure) | Документация интерфейса, маски разрешённых токенов, окончания грамматики и формата диалога. | Использованы для проверки runtime. В анализе сохранены исходные IDs сервера; декодированный текст не токенизируется заново. |
