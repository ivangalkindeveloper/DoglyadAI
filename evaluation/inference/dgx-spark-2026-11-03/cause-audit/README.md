# Причина повторов: проверка запроса и вероятностей токенов

4 ноября 2026 года. Все исследования синтетические.

Подтверждён механизм продолжения цикла: **MedGemma 4B повышает вероятность
повторения уже сгенерированного текста**. Закрытие JSON разрешено, но становится
маловероятным. Отдельное вмешательство в число копий текста воспроизводит этот
эффект без JSON-грамматики.

Найден конкретный фактор нашего запроса: **справочник `contextualStrings`**.
Модель использует его термины как список недостающих сведений об исследовании.
Удаление только справочника устранило все четыре остановки по лимиту на парном
наборе из 16 запросов. Это подтверждает влияние справочника на данный набор,
но не делает его единственной возможной причиной повторов MedGemma.

**Готовое исправление продукта не подтверждено.** Без справочника остались
ошибки измерений, пропуски противоречий и два ответа с двукратным повтором
замечания. Исправление речевого термина также не выполнено. Рабочий код,
настройки и контейнеры в этой серии не изменены.

## Условия и воспроизводимость

- DGX Spark, существующий `google/medgemma-4b-it`, BF16.
- Ревизия весов и токенизатора: `290cda5eeccbee130f987c4ad74a59ae6f196408`.
- vLLM 0.28.0, XGrammar 0.2.3, `disable_any_whitespace=true`.
- Запросы последовательные; штатный `max-num-seqs=4` сохранён.
- Во всех полных диагностических запросах `max_tokens=2048`, без `maxLength`,
  `repetition_penalty=1.0`. Рабочий penalty=1.05 не менялся.
- Параметры выборки взяты из замороженного `expanded-baseline-cases.json`:
  greedy и temperature=0.3 с указанными seed. В паре меняется только
  исследуемая часть запроса.
- Проба использует приватный API движка. Прикладные маршруты, App Check,
  SSE-клиент и production-защита от повторов не меняются. Это не полный тест iOS.

Выполнена **31 полная генерация**, два свободных продолжения по максимум
192 токена и 40 запросов на один токен для измерения вероятностей.
Разогрев исключён. Все полные ответы и token IDs сохранены.

Три повторных контрольных запроса побитно совпали по входным и выходным
token IDs с предыдущей серией. Поэтому изменение ответа в опытах нельзя
объяснить тем, что контрольный сбой перестал воспроизводиться.

## 1. Где возникает смешение данных

В `backend/main/app/prompt/prompt_factory.py`:

- `system_prompt()` добавляет `medicalTermCorrectionPrompt` к заданию
  составить протокол, рекомендации и замечания;
- `build_prompt()` добавляет весь `contextualStrings` после данных пациента;
- тот же справочник и инструкция уже используются в `voice_prompt()` и
  `voice_system_prompt()` для разбора речи.

Инструкция прямо запрещает считать словарь данными пациента. Но модель
нарушает её: в `no-grammar-results.jsonl`, `conflict-sample-42`, замечание
перечисляет термины словаря как неуказанные характеристики. В сбое мочевого
пузыря цепочка вопросов последовательно переходит к терминам из справочника,
включая другие структуры, затем повторяется. Это наблюдение в сыром выходе,
а не предположение по названию поля.

## 2. Изменение одного фактора

Три запроса: нормальное описание щитовидной железы, противоречивое описание
щитовидной железы и описание мочевого пузыря с продиктованным заключением.

| Изменение относительно контроля | Завершились сами | Дошли до лимита | Сырой JSON соответствует схеме | Приняты main |
|---|---:|---:|---:|---:|
| Нет изменений | 1/3 | 2/3 | 1/3 | 1/3 |
| Удалён только справочник | 3/3 | 0/3 | 3/3 | 3/3 |
| Удалена только инструкция исправления терминов | 3/3 | 0/3 | 3/3 | 2/3 |
| Удалены оба элемента | 3/3 | 0/3 | 3/3 | 3/3 |
| Отключена только JSON-грамматика | 3/3 | 0/3 | 0/3 | 0/3 |

Последний вариант возвращает JSON в Markdown-ограде. Удаление ограды только
в диагностике позволяет проверить содержимое, но не делает сырой ответ
валидным по контракту. В нём остаётся смешение словаря с данными пациента.
Отключение structured output поэтому не принято как исправление.

Проверка полного набора:

| Вариант | Запросов | Остановка по лимиту | Повторы по действующему детектору | Приняты main |
|---|---:|---:|---:|---:|
| Исходный запрос, предыдущая серия | 16 | 4 | 4 | 11 |
| Удалён только справочник | 16 | 0 | 0 | 15 |

Четыре прежних остановки по лимиту: `conflict-sample-0`,
`conflict-sample-42`, `bladder-dictated-sample-42`,
`bladder-template-sample-42`. Все завершились без обрезания.

Ноль в столбце детектора не означает отсутствие любого дублирования:
`conflict-greedy-0` и `conflict-sample-0` дважды повторяют одно замечание.
Детектор требует более выраженного повтора. В `report-sample-0` main
обнаруживает `reportMeasurementsMismatch`. В остальных ответах сохраняются
семантические ошибки, которые main не проверяет полностью:

- конфликт мочевого пузыря остаётся без замечания;
- в явном исправлении сохраняются старое отрицание и новая находка;
- «анофагенное» не исправлено;
- замечания щитовидной железы не называют оба противоречащих утверждения.

Таким образом, удаление словаря — подтверждённое воздействие на появление
длинных циклов в этом наборе. Это ещё не полноценная реализация требований.
Изменение длины и содержания входа происходит одновременно; опыт не
разделяет эффект конкретного слова, положения справочника и длины контекста.
Нельзя переносить частоту 4/16 на реальных пользователей.

## 3. Почему модель продолжает цикл

`probe_tokens.py` использует исходные token IDs. Повторной токенизации
сгенерированного текста нет. Для каждого префикса проверяется маска XGrammar,
а вероятности запрашиваются **без грамматики и без штрафа за повторения**.

Родной `apply_chat_template(..., return_dict=True)` точно воспроизводит
входные IDs всех трёх контрольных запросов. EOS и конец хода — 1 и 106;
107 — перевод строки. Перестановка этих токенов не требуется.

Во всех 16 проверенных точках двух ошибочных ответов:

- самый вероятный сырой токен продолжения разрешён грамматикой;
- токен `"}` разрешён грамматикой;
- raw-вероятность EOS очень мала: маска не блокирует желаемое моделью
  высоковероятное завершение в этих точках.

У мочевого пузыря наблюдалось:

| После предложения замечания | P(следующий токен ` Если`) | P(следующий токен `"}`) |
|---|---:|---:|
| 2 | 13.4933% | 0.97745% |
| 3 | 75.6756% | 0.44998% |
| 5 | 98.3861% | 0.03513% |
| 8 | 99.5196% | 0.00481% |
| 20 | 99.9019% | 0.000449% |

Обе вероятности строки таблицы взяты из одного ответа `logprob_token_ids`.
Это вероятности отдельных токенов, а не сумма всех возможных путей завершения.
Они измерены без temperature-масштабирования. Значения top-20 и отдельного
запроса выбранных токенов могут немного различаться между вычислениями BF16;
вывод основан на порядке величин и разрешённости токенов.

После завершённого нормального JSON грамматика разрешает EOS106 и запрещает
лишний перевод строки. Поэтому механизм остановки способен завершить ответ.
В проблемном ответе до закрытия JSON модель ещё не дошла.

Свободное продолжение ошибочного префикса мочевого пузыря также повторяется
до диагностического лимита 192 токена. Продолжение щитовидной железы повторяет
часть содержания, затем закрывает JSON. Нельзя утверждать, что каждый
свободный ответ обязательно зацикливается.

## 4. Контролируемое увеличение числа повторов

`probe_copies.py` берёт один фактический блок из трёх предложений ошибочного
ответа щитовидной железы. Сохраняет исходный запрос и префикс до этого блока.
Затем меняет только число копий **одних и тех же token IDs**. Все префиксы
допустимы по исходной схеме. Для измерения грамматика отключена.

| Копий блока в префиксе | P(` Также`, начало следующего повторения) | P(`"}`) |
|---|---:|---:|
| 1 | 83.971% | 1.19778% |
| 2 | 92.341% | 0.42762% |
| 4 | 97.522% | 0.10727% |
| 8 | 98.961% | 0.01147% |
| 16 | 99.569% | 0.002006% |

В каждой строке greedy выбирает ` Также`. Этот опыт подтверждает эффект
числа копий на предпочтение следующего повтора; это уже не только наблюдение
за разными предложениями естественного ответа. Длина префикса растёт вместе
с числом копий. Отдельный эффект позиции от эффекта повторённого содержания
этим опытом не измеряется.

Это согласуется с механизмом self-reinforcement, описанным в
[Learning to Break the Loop, NeurIPS 2022](https://arxiv.org/abs/2206.02369).
Работа исследует другие модели. Причину в MedGemma подтверждают наши
измерения, а не перенос её результатов без проверки.

## 5. Роль structured output и движка

Валидная схема ограничивает допустимые токены. Она не требует выбрать
закрывающую кавычку именно сейчас. Повторённая медицинская фраза внутри
строки остаётся допустимым JSON-префиксом. До закрытия объекта EOS запрещён
правильно. Ограничение общего числа токенов завершает такую генерацию
ошибкой, а не готовым протоколом.

Ограничение формата влияет на весь путь генерации: без него модель может
выбрать Markdown-ограду и переносы. Поэтому отсутствие цикла в свободном
запуске не доказывает баг реализации JSON-маски. Такое изменение распределения
при constrained decoding исследуется в
[Grammar-Aligned Decoding](https://arxiv.org/abs/2405.21047).

Предыдущие испытания подтверждают воспроизведение повторов в Transformers
и SGLang; см. [сравнение движков](../ENGINE_COMPARISON.md) и
[проверку формата](../FORMATTING.md). Новые опыты не повторяют загрузку этих
движков. Совокупность данных не подтверждает дефект SSE, параллелизма или
ошибку stop-token как причину исследуемого сбоя.

Проверка закрытого JSON полезна только после его фактического появления.
Она не исправляет цикл внутри ещё открытого поля. `maxLength` принудительно
закрывает поле и может оборвать смысл; он не обучает модель завершать мысль.

## 6. Практическое следствие

Подтверждённое место для исправления — сборка задания, которое одновременно
просит исправлять речь по большому справочнику, писать протокол и искать
проблемы исходного описания. Справочник уже доступен этапу разбора речи.
Следующий кандидат должен передавать генератору протокола проверенные данные
исследования без полного справочника. Исправление терминов нужно сохранить
на этапе, где доступен исходный транскрипт.

Принимать кандидат следует отдельно по завершению, сохранению измерений,
коррекции речевых ошибок и обнаружению противоречий. Замена всех замечаний
на `null`, удаление повторов после генерации и обрезание строки не считаются
исправлением. Если 4B не выполняет эти задачи после разделения, потребуется
адаптация модели на целевой задаче или выбор модели по проверенному набору.
Замена движка сама по себе не устраняет измеренный механизм повторения.

## Артефакты

- `prepare.py`, `prepare_expanded.py`: точные вмешательства в замороженные запросы.
- `*-cases.json`, `*-results.jsonl`: входы и полные необработанные выходы.
- `token-traces.json`, `token-probe.jsonl`, `copies-probe.jsonl`: исходные IDs,
  маски и измерения; скрипты `probe_tokens.py`, `probe_copies.py`.
- `analyze.py`, `*-validation.json`, `summary.json`: локальная проверка main,
  схемы и повторов. Медицинская корректность не следует из `main_valid=true`.
- `*-runtime-before.json`, `*-runtime-after.json`, `*-other-activity.json`:
  контейнеры не изменены, остальные движки не генерировали. Все три движка
  после опытов готовы и свободны.
- `SOURCES.md`: источники, найденные решения и границы их применимости.

Первый запуск token-пробы остановился до генерации: в Transformers 5
`apply_chat_template` вернул BatchEncoding вместо списка IDs. Сравнение
исправлено явным извлечением `input_ids`; повторный запуск подтвердил точное
совпадение. Это ошибка диагностического скрипта, не шаблона приложения.

Для повторной проверки новых результатов локально:

```bash
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-03/cause-audit/analyze.py
```

Полные запросы запускает `run_experiment.py <manifest.json>` на DGX с
соседним каталогом `schema-revision`. Для повторного запуска нужны новые имена
вариантов: существующие результаты намеренно не перезаписываются.
