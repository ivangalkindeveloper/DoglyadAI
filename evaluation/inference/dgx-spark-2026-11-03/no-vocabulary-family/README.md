# Проверка моделей после удаления справочника из генерации протокола

Дата: 4 ноября 2026 года.

**Завершены все 60 генераций на DGX. Зацикливание не воспроизвелось.**
Все ответы закрыли JSON и завершились с `finish_reason=stop`. Ни один запрос
не достиг лимита токенов. Проверку main прошли 58 ответов из 60.

Это результат ограниченного синтетического набора, а не гарантия отсутствия
повторов на любом вводе. Остались ошибки содержания: пропуски противоречий,
потеря измерений и добавление сведений без источника. Удаление справочника
сохранено в коде по запросу пользователя; другие параметры не менялись.

## Ошибки содержания

- `4b-working`, `conflict-sample-42`: пропущены размеры левой доли и объёмы
  долей из входного текста. Main отклоняет ответ с `reportMeasurementsMismatch`.
- `15-4b-working`, `conflict-greedy-0`: пропущен общий объём щитовидной железы
  13,7 мл. Main отклоняет ответ с тем же кодом.
- В основной серии у каждой модели есть пять запросов с противоречием.
  4B возвращает три пустых замечания и два замечания, которые не называют
  противоречие. 1.5 4B и 27B возвращают `descriptionRemarks=null` во всех
  запросах основной серии, включая эти пять.
- В явном исправлении врача модели 4B сохраняют старое отрицание вместе с
  новой находкой. 27B использует исправленную находку, но добавляет состояние
  стенки и другие сведения, которых во вводе не было.
- В `bladder-template-sample-42` модель 27B называет объём 240 мл остаточным,
  хотя во вводе не сказано, что измерение выполнено после мочеиспускания.
- Сырой термин «анофагенное» сохраняется у всех моделей. Этот контроль
  передаёт речевую ошибку прямо в генерацию протокола, минуя разбор речи.
  Справочник сохранён именно на этапе разбора речи; его качество данной
  GPU-серией не проверяется.

Таким образом, отсутствие цикла не означает выполнение всех требований
к содержанию протокола. Успех `main_valid` означает прохождение текущих
проверок структуры и содержания, а не полную медицинскую достоверность.
Подробные наблюдения: `review-notes.json`.

## Изменение

`PromptFactory.system_prompt()` больше не добавляет `medicalTermCorrectionPrompt`
к генерации протокола. `build_prompt()` больше не добавляет `contextualStrings`.
Сборка запроса разбора речи сохраняет справочник и инструкцию исправления терминов.
Общий сборщик применяется к development и production.

Обновлён существующий RU/EN-тест генерации протокола и README main backend.
Полный pytest main, Ruff, mypy и проверка форматирования прошли.
`make check-architecture` сообщает о 13 прежних `swift.view-fragment` в iOS.
Сведения: `code-verification.json`.

## Условия испытаний

Для каждой модели — `google/medgemma-4b-it`, `google/medgemma-1.5-4b-it`,
`google/medgemma-27b-it`:

- 16 запросов с рабочим `repetition_penalty=1.05`;
- четыре прежних сбойных примера с диагностическим `repetition_penalty=1.0`.

Набор взят из `prompt-repair/expanded-baseline-cases.json`: нормальное и
противоречивое описания щитовидной железы при разных seed, мочевой пузырь,
почки, явное исправление врача, продиктованное заключение, речевая ошибка,
шаблон и английский ввод. Все данные синтетические, без фотографий.

Промпт и схема строятся реальным `ReportGenerationService.prepare()`.
Транспортное тело собирает `InferenceService._prepare()`, а тело для vLLM —
`VLLMService._prepare()` в отдельном процессе. HTTP-приложения не запускаются,
App Check не отключается. Проверено равенство промптов и схем обеих сред.

Seed добавлен для воспроизводимости. `stream_options` и возврат token IDs
добавляет диагностическая проба. `top_p` и `top_k` не переопределяются: действуют
настройки движка, как в рабочем пути. Предыдущая причинная серия задавала
`top_p=1` и `top_k=-1` явно; её результаты не являются строгим парным сравнением
со всей этой серией. `max_tokens=2048`, ограничения `maxLength` отсутствуют.

## Запуск и проверка

`prepare.py` сохраняет `*-cases.json` и хеши кода в `source.json`.
`run_family.py` последовательно запускает три модели через `run_experiment.py`.
Запуск выполняется внутри существующих контейнеров без их пересоздания.
Локальный `probe_engine.py` содержит пробу движка; соседние каталоги
`schema-revision` и `runtime-comparison` — проверки готовности.
Существующие результаты не перезаписываются.

Первый запуск выполнил 16 рабочих запросов 4B, затем остановился перед
разогревом дополнительной серии: общий скрипт требовал пример
`report-greedy-0`, которого в наборе из четырёх сбойных примеров нет.
В локальной копии пробы добавлен выбор первого примера как запасного.
Неудачная попытка сохранена в `attempt1/`. В ней нет дополнительных
полных генераций. Готовые 16 ответов не перезапускались; продолжение
зафиксировано в `controller-resume.log`.

`analyze.py` проверяет необработанный ответ по схеме и через main.
Медицинская корректность не следует из успешной структурной проверки.
Проведён просмотр замечаний, отрицаний, измерений и повторов. Он выявил
описанные выше ошибки; независимая клиническая оценка не выполнялась.

Хеши актуального кода сверены с замороженными запросами. Снимки
`*-runtime-before.json` / `*-runtime-after.json` подтверждают сохранение
контейнеров, образов, команд запуска и времени старта. Счётчики других
моделей не менялись во время каждой серии. Финальная проверка подтвердила
готовность и отсутствие активных запросов у всех трёх движков.
Итоговые проверки: `verification.json`, `final-runtime.json`.

Для использования изменения нужен локальный main backend, запущенный из
обновлённого кода. Обновление inference-образа на DGX для изменения промпта
не требуется.

Эта серия проверяет генерацию на GPU и валидацию main. Она не заменяет
полный сетевой тест iOS → main → inference с App Check.
