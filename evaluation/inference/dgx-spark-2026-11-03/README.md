# Зацикливание MedGemma: диагностика 3 ноября 2026 года

Последняя проверка 4 ноября: из генерации протокола удалены `contextualStrings`
и инструкция работы со справочником. Разбор речи сохраняет оба элемента.
**Все три MedGemma проверены на DGX: по 20 запросов, всего 60.** Все ответы
завершились сами; повторов внутри полей и остановок по лимиту не обнаружено.
Main принял 58/60 ответов. Остались ошибки измерений и содержания, поэтому
это не подтверждение полной корректности протоколов.
Подробности: [no-vocabulary-family/README.md](no-vocabulary-family/README.md).

Новое исследование 4 ноября: **подтверждены механизм усиления повторов и влияние
справочника `contextualStrings` в нашем запросе**. Удаление только справочника
устранило четыре остановки по лимиту на парном наборе из 16 запросов.
Отдельный опыт с числом копий текста показал рост вероятности продолжить
повтор с 84% до 99,6% без JSON-грамматики. Закрывающий токен разрешён.
Полноценное исправление ещё не принято: остались ошибки содержания и
двукратные повторы. Рабочие сервисы не менялись.
Измерения, ограничения и источники: [cause-audit/README.md](cause-audit/README.md).

Обновление 4 ноября: выполнено **120 генераций без обрезания полей**.
Короткая инструкция убрала циклы на контрольном наборе, но перестала возвращать
замечания к противоречиям. Она отклонена. В коде удалены ограничения `maxLength`;
надёжное исправление зацикливания пока не подтверждено.
Результаты и сохранённая конфигурация: [prompt-repair/README.md](prompt-repair/README.md).

Проверены **MedGemma 1.5 4B и 27B**: ещё 32 генерации на том же наборе,
с ограничениями длины и без них. Повторы и обрезания не воспроизвелись.
Main принял 14/16 ответов 1.5 4B и 16/16 ответов 27B. При этом обе модели
пропустили противоречие в исходном описании. Подробности и ограничения:
[schema-family/README.md](schema-family/README.md).

Выполнены 37 повторных генераций с изменённой JSON Schema и явной инструкцией
формата: [schema-revision/README.md](schema-revision/README.md). В рабочей
серии циклы не обнаружены, но 2 из 8 ответов оборваны ограничением длины.
Без ограничения один из этих ответов трижды повторяет большой блок, затем
закрывает JSON. Main отклоняет такие ответы. Полное исправление не достигнуто.

Последнее дополнение: **сравнение vLLM и SGLang при лимитах 1 и 4**.
Выполнены 80 полных проверок и 36 запросов для измерения скорости.
Лимит 1 не устранил циклы. Все 18 последовательных ответов vLLM совпали
между лимитами 1 и 4. SGLang сохранил циклы в 3 из 13 контрольных запросов
при каждом лимите; vLLM — в 4 из 13. На четырёх одновременных коротких запросах
получено 109.0 токенов/с суммарно у SGLang и 112.4 у vLLM.
Условия, ограничения и результаты: [ENGINE_COMPARISON.md](ENGINE_COMPARISON.md).

Предыдущая серия: **43 новые генерации** с рекомендацией из обсуждения
Google, XGrammar 0.2.8 и контрольной Qwen3-4B-Instruct-2507.
Надёжного исправления MedGemma настройками не найдено. Qwen завершила все
26 запросов через vLLM и Transformers без цикла до лимита токенов, сохранив
JSON Schema и BF16. Это текстовый контроль, не проверка клинического качества.
Подробности: раздел «Дополнительное исследование: рекомендации Google и
другая модель 4B» в [FORMATTING.md](FORMATTING.md) и `deep-investigation/`.

Статус: подтверждена чувствительность MedGemma 4B к форматированию JSON.
В контролируемом продолжении компактный формат снизил вероятность завершения
последнего строкового поля; начавшийся цикл модель поддерживает сама.
Это подтверждено проверкой вероятностей токенов и независимым запуском через
Transformers. Однако последующая серия не подтвердила, что разрешение переносов
надёжно устраняет повторы: при повторном полном запуске свободный формат тоже
дал цикл. Компактный формат нельзя считать единственной причиной всех сбоев.

Полное устранение повторов для всех моделей не подтверждено. У 1.5 4B остался
другой зацикленный ответ при разрешённых переносах. Эти результаты не
подтверждают качество моделей для клинического применения.

Реализация и результаты последующего опыта с распознаванием завершённого JSON:
[JSON_COMPLETION.md](JSON_COMPLETION.md).

Последующая проверка ограниченных пробелов, отступов, инструкций и режимов
`stream=true` / `stream=false`: [FORMATTING.md](FORMATTING.md). Новые варианты
не приняты для рабочего сервиса; ниже сохранены исходные результаты диагностики.

Дополнительно выполнены 33 полные генерации MedGemma 4B: vLLM с XGrammar,
vLLM с Guidance и Transformers с XGrammar. Оба альтернативных варианта
сохранили зацикливания. На историческом запросе greedy-ответ Transformers
совпал с vLLM во всех 2048 токенах. На текущем обычном запросе результаты
разошлись, поэтому это не утверждение об эквивалентности движков вообще.
См. раздел «Полная генерация: XGrammar, Guidance и Transformers» в
[FORMATTING.md](FORMATTING.md) и исходные данные в `runtime-comparison/`.

## Установленный механизм

В `deploy/inference/compose_document.py` генератор задаёт
`--structured-outputs-config '{"backend":"xgrammar","disable_any_whitespace":true}'`.
Та же настройка есть в двух Compose-файлах для одиночного inference-хоста.
Она разрешает фиксированные разделители, но запрещает свободное форматирование
JSON, в том числе переносы между полями. Параметр появился в коммите
`64ae8f4` (`Fix constrained voice JSON generation`): комментарий указывает
цель — предотвратить повторение пустых строк. Настройка применяется ко всем
задачам модели, включая длинные протоколы.

### Контроль с одинаковым текстом

Из неудачного ответа взято начало до точки в третьем предложении
`descriptionRemarks`. Инструкции и все строковые значения сохранены.
Второй вариант отличается только пробелами и переносами **вне JSON-строк**.
Оба продолжения выполнялись без JSON-ограничений, с температурой 0 и
`repetition_penalty=1.0`.

| Формат начала ответа | Продолжение | Завершение |
|---|---|---|
| Одна строка | 256 токенов, 7 полных копий повторяющегося предложения | `length`, JSON не закрыт |
| Переносы между полями | 5 токенов: закрытие строки и объекта | `stop`, полный JSON успешно разобран |

Артефакт: `formatting-only-continuation.jsonl`. Его `valid_json` проверяет
только новый суффикс, поэтому имеет значение `false` в обоих случаях.
Проверка склейки `messages[-1].content + text` для `pretty_prefix` успешна.

Перед точкой модель оценила токен `."`, который завершает строковое поле:

- компактный контекст: вероятность **9.29%**;
- тот же текст с переносами между полями: **73.32%**.

Это вероятности до применения температуры и маски JSON. Закрывающий токен
разрешён грамматикой в обоих форматах. Следовательно, здесь проблема не в
запрете закрывающей кавычки: меняется распределение самой модели из-за
форматирования уже сгенерированного контекста.
Артефакты: `prefix-before-punctuation.jsonl` и
`prefix-pretty-before-punctuation.jsonl`, `baseline-0`, позиция 2.

### Полные генерации

Промпт, данные, веса, температура 0.3 и нейтральный штраф повторений сохранены.
Использован один и тот же XGrammar. В обеих ветках схема переведена в EBNF;
отличается только `any_whitespace`. Компактная ветка с seed 0 также повторяет
исходный результат `response_format=json_schema` с 59 копиями предложения.

| Seed | Компактный JSON | Переносы разрешены |
|---|---|---|
| 0 | 2048 токенов, `length` | 492 токена, `stop` |
| 42 | 2048 токенов, `length` | 714 токенов, `stop` |
| 123 | 2048 токенов, `length` | 656 токенов, `stop` |

Артефакты: `grammar-seed0.jsonl`, `grammar-seeds42-123.jsonl`.
Часть диагностики выполнялась с перекрывающимися запросами; время не является
бенчмарком, а seed не гарантирует побитовую воспроизводимость CUDA-вычислений.
В завершённом ответе seed 42 сохранились повторения и ошибки содержания.
Завершение JSON не следует приравнивать к правильному медицинскому ответу.

### Независимая проверка модели

Та же MedGemma 4B загружена через `Gemma3ForConditionalGeneration` из
Transformers 5.15.1, BF16, SDPA. Переданы **точные ID токенов** из проверки
vLLM. В процессе не использовались vLLM, XGrammar или штраф повторений.

| Позиция | Вероятность токена ` Не` в vLLM | В Transformers |
|---|---|---|
| После седьмого предложения замечаний | 95.55% | 95.88% |
| После одиннадцатого предложения | 98.8437% | 98.8415% |

Свободное greedy-продолжение в Transformers дало четыре полные копии той же
фразы за 128 токенов. Это подтверждает, что уже начатый цикл поддерживается
самой моделью, а не повторной отправкой SSE-фрагментов или особенностью
вычисления этих позиций в vLLM. Проверка заданного начала ответа не означает,
что Transformers самостоятельно пройдёт ту же траекторию с первого токена.

Артефакт: `transformers-reference.jsonl`. Для освобождения памяти временно
остановлен только контейнер MedGemma 4B. После проверки он запущен с прежними
настройками и достиг `healthy`. Остальные контейнеры не перезапускались.

### Границы вывода

- Найден пусковой фактор конкретного воспроизведённого сбоя 4B и механизм
  закрепления повтора. Нет доказательства, что этот фактор объясняет любой
  возможный повтор MedGemma.
- У 1.5 4B с противоречивым входом разрешённые переносы помогли seed 0,
  но seed 42 всё равно дошёл до 2048 токенов. Это не универсальное исправление.
  Артефакт: `grammar-15-4b-whitespace.jsonl`.
- Просто удалить глобальный флаг без проверки нельзя считать завершённым
  исправлением: нужно также проверить исходный сценарий разбора речи,
  ради которого ограничили пустые строки.
- Квантование, веса, рабочие промпты и параметры развёртывания не менялись.
  Остановка и запуск исходного 4B-контейнера были нужны только для независимой
  проверки. Исследование не добавляет исправление в рабочий сервис.

## Условия

- DGX Spark, существующие работающие vLLM-контейнеры, без перезапуска и смены весов.
- Синтетическое описание щитовидной железы из development-каталога проекта.
  Реальные данные пациентов не использовались.
- Температура 0.3, максимум 2048 токенов, `repetition_penalty=1.0`.
- Один запрос на модель. Проверки 27B и 1.5 4B выполнялись одновременно на общем
  GPU; их время нельзя напрямую сравнивать со временем отдельных запусков 4B.
- Прямой запрос к приватному vLLM из inference-контейнера. Публичные проверки
  App Check не изменялись. Ответ собирался из исходных SSE delta.
- В тестах `conflict` к исходному «без очаговых изменений» добавлено
  «В правой доле выявлено очаговое образование». Ожидалось замечание о
  противоречии. Успех проверки JSON не означает выполнения этого требования.
- По умолчанию эксперимент снимает `maxLength` у `descriptionRemarks`, чтобы
  увидеть продолжение ответа. `--bounded` сохраняет ограничение 512 символов.

Последняя проверка сопоставима с вариантом `schema_prompt` в
`old-remarks-ablation.json`: одинаковые данные, инструкции и seeds 0/42.
Изменено наличие `response_format`. При seed 0 принудительный JSON привёл к

`max_sentence_copies` — вспомогательная метрика по всему ответу. Две копии
предложения могут быть обычным пересечением описания и заключения. Это не
автоматический диагноз зацикливания.

## Вывод первого этапа

Найденный цикл возникает до main backend и iOS. Изменение клиентского
накопления текста не устранит этот воспроизведённый сбой. На результат влияют
инструкция замечаний и принудительный JSON-формат. Конкретный дефект движка
пока не доказан. Простое отключение structured output нарушает контракт,
а ограничение длины и штраф повторений не доказывают устранения причины.

В этой серии изменялись только экспериментальные запросы. Рабочие промпты,
параметры моделей и развёрнутые сервисы по результатам серии не менялись.

## Воспроизведение последнего сравнения

Из корня репозитория, с доступом к существующему DGX по SSH:

```bash
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-03/diagnose_repetition.py --old-remarks --variants schema_prompt_free --seeds 0 42 --output old-remarks-free-repeat.json
```

Используйте новое имя результата, чтобы сохранить исходные измерения.
Точные запросы, схемы, ответы и метрики сохранены в JSON-артефактах.
