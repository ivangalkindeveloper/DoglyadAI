# Hulu-Med 7B BF16 на DGX Spark

Развёртывание завершено 2026-11-12. Все пять движков имеют статус `healthy`.
Новая модель доступна в каталогах development и production по Pro.
В локальную карту endpoint добавлена одна запись с тем же адресом общего API,
что у Hulu-Med 32B. Прежние значения карты сохранены.

## Источник и запуск

- Модель: [ZJU-AI4H/Hulu-Med-7B](https://huggingface.co/ZJU-AI4H/Hulu-Med-7B).
- Revision: `258594714a0d3835eb2c9e4cc165a4242e606d71`.
- Четыре файла весов: 16 089 587 104 байт, около 14,98 GiB.
- LFS SHA256 всех файлов проверены. Все 779 тензоров имеют dtype BF16.
  Квантование не выполнялось; веса не менялись.
- Каталог DGX: `/opt/doglyad/models/hulu-med-7b-bf16-20261112`.
- Сервис: `vllm_hulu_med_7b`, без опубликованных портов.
- Образ: `sha256:a43025e228727bfac14ea75aeed1cdc086b25c778584fc7593421383de2f724d`,
  ARM64, vLLM 0.28.0 с проверенным адаптером Hulu-Med.
- Рабочий контекст 16384; BF16 KV-кэш 2 GiB; до восьми последовательностей;
  до шести изображений. Eager execution и prefix caching; без N-gram и CUDA Graphs.
- Архитектурное окно 32768 отображается в каталоге приложения отдельно от рабочего лимита.

Исходный процессор совпал с источником уже проверенного процессора 32B.
В рабочую копию перенесены те же изменения совместимости с Transformers 5
и optional Decord. Код обработки изображений отличается только комментариями
и пробелами; AST совпадает. Нормализация изображений сохранена.
Визуальный бюджет процессора ограничен до 2048 токенов, как у работающей 32B.
Штатный resize уменьшает большие кадры перед обработкой.
Шаблон чата получает `image_token: "<image>"`.
Изменения метаданных описаны в `runtime-preparation.json`; исходник сохранён отдельно.

## Проверки

- 16 проверок runtime: текст, JSON, поток RU/EN, язык ответа,
  кадры 224×224, 1024×768 и 4032×3024, шесть цветных объектов в правильном
  порядке, восемь одновременных коротких арифметических запросов.
- Оба протокола прошли `ReportGenerationService.complete()` main backend.
- Ещё семь генераций: отдельные запросы к 7B и 32B, затем по одному запросу
  ко всем пяти моделям одновременно. Все семь ответов прошли валидатор main.
- Штатный read-only preflight подтвердил профиль, образы, параметры,
  веса read-only, model ID, приватность портов, маршруты и `healthy`.
- 25 файлов рабочего checkpoint повторно сверены с manifest.
- Четыре прежних движка сохранили ID контейнеров, image ID и счётчики перезапусков.
  Общий backend сохранил image ID; пересоздание добавило маршрут новой модели.
- Обе ручки общего API через локальный SSH-туннель возвращают `401` без токена.
  App Check не отключался.
- 54 теста инфраструктуры и 39 тестов конфигурации main прошли.
  Ruff и соответствие сгенерированного Compose профилю проверены.

`make check-architecture` по-прежнему находит 12 нарушений `swift.view-fragment`
в существующих iOS-компонентах вне этих изменений. Swift-код здесь не менялся.

Успешная генерация проверена через `VLLMService` внутри развёрнутого backend
и реальные HTTP-запросы к приватным движкам. Сквозной запуск через iOS с
пользовательским App Check токеном отдельно не выполнялся.

## Память

| Замер | Доступная RAM |
|---|---:|
| До добавления 7B | около 32,7 GiB |
| После загрузки, тестов и аудита | 10,37 GiB |
| Минимум при совместном тесте пяти моделей | 9,76 GiB |

Финальный swap: около 15,70 GiB из 16 GiB занят. За отдельный 15,63-секундный
интервал аудита прочитаны две страницы swap и записана одна, по 4096 байт.
Это замер во время аудита, а не измерение swap под всей нагрузкой.

Совместный тест выполнял один текстовый протокол на модель. Он не проверяет
сорок полных протоколов или одновременную обработку изображений всеми моделями.
Два GiB KV-кэша дают около 37 440 токенов суммарной ёмкости: восемь слотов
не означают восемь одновременно активных запросов с полным контекстом 16384.

## Предварительное сравнение Hulu-Med

Один и тот же синтетический английский запрос, system prompt и JSON Schema.
Температура 0, prefix caching включён. Измерения тёплые, по одному примеру.

| Модель | Первый delta, с | Полный ответ отдельно, с | Ответ, символов | Полный ответ при работе всех пяти, с |
|---|---:|---:|---:|---:|
| 7B BF16 | 0,087 | 7,44 | 362 | 25,30 |
| 32B NVFP4 | 0,857 | 8,90 | 313 | 27,20 |

Это предварительные измерения клиентской задержки. Ответы имеют разную длину,
поэтому таблица не является строгим сравнением токенов в секунду.
Протоколы и изображения синтетические. Медицинское качество на реальных
исследованиях и качество двух размеров модели здесь не оценивались.

## Применение каталога

Перезапустите локальный main backend после обновления конфигов и endpoint map.
Заново откройте приложение, чтобы оно загрузило список из пяти моделей.
Локальный SSH-туннель `127.0.0.1:18100` проверен и работает.
Облачные main VM в рамках этой задачи не обновлялись.
