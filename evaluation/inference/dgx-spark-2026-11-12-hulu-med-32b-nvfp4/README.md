# Развёртывание Hulu-Med 32B NVFP4 на DGX Spark

Дата: 2026-11-12. Цель: добавить четвёртую модель к действующему inference API.
Развёртывание завершено. Все четыре движка имеют статус `healthy`.
Прошли 15 автономных проверок и отдельная проверка кадра 4032×3024.
Итоговый замер: **32,71 GiB доступной RAM**.
Три MedGemma сохранили прежние ID контейнеров, образы и счётчики перезапусков.

## Конфигурация

- Логический ID: `ZJU-AI4H/Hulu-Med-32B`.
- Каталоги development и production: `Hulu-Med 32B`, `format: NVFP4`, Pro.
- Описания RU/EN находятся в `l10n.json` обоих окружений.
- `contextLength: 32768` — справочное окно исходной модели.
- Рабочий контекст DGX: 16384; BF16 KV-кэш 4 GiB; до восьми последовательностей.
- До шести изображений. Eager execution и prefix caching; без N-gram и CUDA Graphs.
- Контейнер: `vllm_hulu_med_32b`, без опубликованных портов.
- Общий backend получает четвёртую запись в `VLLM_ENDPOINTS`.
- В локальную карту `backend/main/secrets/inference_endpoints.json` добавлена
  только новая запись с тем же endpoint, что у MedGemma. Значения прежних записей сохранены.

Веса: [ivangalkindeveloper/Hulu-Med-32B-NVFP4](https://huggingface.co/ivangalkindeveloper/Hulu-Med-32B-NVFP4),
commit `5ed563b024f1511837b26830fcb2846cb1fdc501`.
Локальный проверенный ARM64 image ID:
`sha256:a43025e228727bfac14ea75aeed1cdc086b25c778584fc7593421383de2f724d`.
Веса находятся в `/opt/doglyad/models/hulu-med-32b-nvfp4-20261112`.
Исходный каталог публикации сохранён отдельно.

## Исправления интеграции

1. Исходный `chat_template.json` требует переменную `image_token`.
   `HulumedProcessor.apply_chat_template()` передаёт её сам; HTTP renderer
   vLLM этого не делал. Изображения вызывали `UndefinedError`.
   Профиль теперь передаёт `chatTemplateKwargs: {"image_token":"<image>"}`
   через `--default-chat-template-kwargs`.
2. Исходный процессор разрешает 16384 визуальных токена. Профилирование
   адаптера с dummy-кадром 448×448 выделяет encoder cache на 2048 токенов.
   Реальный кадр 1024×768 даёт 4015 токенов и получает `400`.
   В отдельной рабочей копии изменён только `preprocessor_config.json.max_tokens`
   на 2048. Штатный resize процессора уменьшает большие кадры, сохраняя их целиком.
   Для 1024×768 проверена сетка 52×39, то есть 2028 визуальных токенов.
   Веса и публичная публикация не менялись. Настройка хранится в
   `deploy/dgx-spark/config/hulu-med-32b-preprocessor.json`.

В генераторе добавлена поддержка проверенного локального image ID,
явного `isRemoteCodeTrusted` и именованных `chatTemplateKwargs`.
Они не добавляют эти параметры в другие модели.

Отдельная проверка однотонного красного кадра дала ошибочный ответ `black`.
Изображение с красным квадратом на белом фоне из исходной технической проверки
модель распознала через HTTP при обоих порядках текста и изображения.
Этот результат не устанавливает причину ошибки на однотонном кадре и не
является сравнением медицинского качества BF16/NVFP4.

## Выполненные локальные проверки

- 54 теста инфраструктуры: успешно.
- 39 тестов конфигурации main: успешно; проверены оба окружения и локализации.
- Ruff и соответствие сгенерированного Compose профилю: успешно.
- `make check-architecture`: неуспешно. Найдены 12 нарушений
  `swift.view-fragment` в существующих iOS-компонентах вне этого изменения.
  Swift-код в рамках развёртывания не менялся.

Два финальных синтетических протокола RU/EN с реальным prompt и JSON Schema main
прошли `ReportGenerationService.complete()`. Проверяются сохранение
измерений, структура и ограничения действующего валидатора.

## Область проверки

Генерация проверяется через `VLLMService` внутри развёрнутого контейнера
backend и реальные HTTP-запросы к приватному vLLM. App Check не отключается.
Обе публичные ручки через SSH-туннель возвращают `401` без токена.
Проверка с пользовательским токеном через iOS и main пока не выполнялась.

Техническая проверка подтверждает интеграцию, но не медицинское качество.
Протоколы и изображения синтетические; данных реальных пациентов нет.
Измерения времени отдельных запусков не являются сравнительным бенчмарком.

## Применение локального каталога

Перезапустите локальный main backend после изменения каталога и карты endpoint.
Заново откройте приложение, чтобы оно загрузило обновлённый список моделей.
Облачные main VM не обновлялись. Общий backend на DGX сохранил прежний image ID;
его пересоздание изменило только маршруты моделей.

Локальный SSH-туннель `127.0.0.1:18100` восстановлен после потери связи.
Обе ручки проверены через него: без токена возвращают `401`.
Настройки Wi-Fi и Tailscale не менялись.
