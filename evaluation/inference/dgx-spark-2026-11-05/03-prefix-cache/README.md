# Повторное использование общего префикса

Статус: завершено для всех трёх моделей. Полные результаты — в [таблице](TABLE.md).

Общий системный префикс сократил время первого непустого фрагмента SSE:

| Модель | Холодный кеш, с | Общий системный префикс в кеше, с |
|---|---:|---:|
| MedGemma 4B | 0,290 | 0,116 |
| MedGemma 1.5 4B | 0,274 | 0,111 |
| MedGemma 27B | 1,048 | 0,477 |

При повторе почти всего исследования результат ещё лучше: у 27B первый
фрагмент пришёл за 0,279 секунды вместо 1,048. При общем длинном префиксе
около 8000 токенов — за 0,271 вместо 5,993 секунды. Это контролируемые
попадания в кеш, а не прогноз для любого нового исследования.

Prefix caching уже включён в рабочем режиме. Исследование проверяет его эффект,
не включает новую оптимизацию и не меняет промпт приложения.

- `application-corrected-cold/warm`: повтор одного синтетического исследования. В конце
  пользовательского текста меняется идентификатор запроса. Прогретый вариант
  может использовать почти весь прежний вход, включая данные исследования.
- `long-cold/warm`: такой же контролируемый опыт с префиксом около 8000 токенов.
- `system-cold/warm`: пользовательские сообщения различаются уже в начале.
  Общими остаются системные инструкции. Этот вариант ближе к запросам разных
  пациентов с одинаковыми настройками протокола.

Первая серия `application-cold/warm` содержала ошибку добавления метки к массиву
текстовых блоков: пробелы в добавленной метке терялись. Это подтверждено
сохранёнными token IDs и [проверкой формата](content-format-parity.json).
Исходные записи сохранены, но исключены из таблицы и выводов. Серия повторена
с корректными блоками под именем `application-corrected-*`. Совпадение token IDs
с каноническими блоками подтверждает [повторная проверка](corrected-content-format-parity.json). Системный префикс,
входы тестов производительности и полные ответы этой ошибкой не затронуты.

Холодные запросы имеют независимые `cache_salt`. Внутри прогретой группы salt
общий. Первый запрос прогревает кеш и не входит в измерение. Каждый измеряемый
запрос выдаёт 16 токенов. Полные медицинские ответы здесь не оцениваются.

Кеш сокращает обработку входа. Он не ускоряет вычисление каждого следующего
токена длинного ответа. В текущем `PromptFactory` общие инструкции уже стоят
перед данными исследования. Различия языка, настроек, схемы и фотографий могут
сокращать общую часть. Этот опыт не измеряет долю попаданий реальных пользователей.

Фактура: `*/*/results.jsonl`, [summary.json](summary.json). В событиях `input`
сохранены точные промпты; события `metrics_*` содержат счётчики кеша.
Сохранённые token IDs позволяют проверить фактически обработанный вход.
[vLLM: Automatic Prefix Caching](https://docs.vllm.ai/en/v0.28.0/features/automatic_prefix_caching/).
