# N-gram speculative decoding

Статус: завершено для всех трёх моделей. Полные результаты — в [таблице](TABLE.md).

N-gram ускорил полные ответы без изменения точности весов. Вариант с восемью
кандидатами был самым быстрым среди проверенных для двух основных сценариев:

| Модель | Протокол: исходно → N-gram 8, с | Диктовка: исходно → N-gram 8, с |
|---|---:|---:|
| MedGemma 4B | 10,07 → 4,63 | 23,38 → 6,61 |
| MedGemma 1.5 4B | 9,18 → 4,28 | 28,88 → 13,60 |
| MedGemma 27B | 64,36 → 38,88 | 38,81 → 21,15 |

Все 117 измеренных ответов завершились естественно и соответствовали JSON Schema.
Повторов длинных предложений не найдено; все 18 цветовых проверок прошли.
Из 99 текстовых ответов 94 прошли валидаторы main. Пять отклонений связаны
с сохранением измерений, а не с незакрытым JSON. У 1.5 4B N-gram 4 дал один
дополнительный отказ относительно исходного режима; у N-gram 8 число отказов
совпало с исходным. Подробности: [validation-failures.json](validation-failures.json).

N-gram 8 — кандидат для следующего этапа проверки. Эти данные не подтверждают
качество на широком клиническом наборе или выигрыш при одновременной нагрузке
4/4/4. Рабочая конфигурация в результате исследования не меняется.

Сравниваются обычная генерация и `method=ngram` с 4 и 8 кандидатами.
Окно поиска — от 2 до 5 токенов. Дополнительная модель не загружается,
веса остаются BF16. Сохраняются четыре слота, контекст, KV-кеш, sampling
и XGrammar с исходной JSON Schema.

N-gram ищет совпадения в уже имеющейся последовательности токенов и предлагает
сразу несколько следующих токенов. Основная модель проверяет эти предложения
совместно. Выигрыш зависит от доли принятых кандидатов и нагрузки на GPU.

Для каждого профиля используются девять разных синтетических сценариев:
шесть протоколов, разбор диктовки и два цветовых изображения. Протокол greedy
и диктовка greedy повторяются трижды. Всего измеряются 13 полных ответов
на профиль; дополнительный прогрев в таблицу не входит.

Лимит ответа — 2048 токенов. Клиент не обрезает ответ на закрывающей скобке.
Тест вызывает vLLM напрямую и допускает до 600 секунд на запрос. В рабочем
inference-сервисе операция ограничена 120 секундами. Успешный ответ движка
дольше 120 секунд не означает успешный ответ через рабочий API. В сводных
данных такие запросы посчитаны отдельно; тайм-аут сервиса не меняется.
Проверяются естественное завершение, JSON Schema, валидаторы main, ожидаемые
цвета и повтор одинаковых предложений длиной от 40 символов. Сохраняются
сравнения входных token IDs и текста с исходным режимом.

Скорость полного ответа может измениться из-за разной длины текста.
Для вывода об ускорении нужно сопоставлять число токенов и совпадение ответа.
Проверки main не заменяют врачебную оценку. Ошибка, присутствующая в baseline,
не считается автоматически следствием speculative decoding.

Два цветовых изображения проверяют подключение vision encoder и соблюдение
простой схемы. Это не УЗИ и не медицинская оценка изображений. Каждый такой
запрос выполняется один раз на профиль, без отдельного прогрева этой формы
входа. Его время нельзя считать устойчивой скоростью анализа изображений.

Измеряется один запрос за раз. Эффект при высокой нагрузке, отдельные draft
models, EAGLE и другие методы в эту серию не входят. Теоретическое сохранение
распределения не гарантирует одинаковый текст при всех численных режимах.

Фактура: `*/*/results.jsonl`, [summary.json](summary.json), исходные сценарии
`../cases-*.json`, команды и ошибки запуска в `../runs/`.
В [COMPARISON.md](COMPARISON.md) сопоставлены время, число токенов, совпадение
текста и доля принятых кандидатов. Счётчики кандидатов включают прогрев.
В [FIRST_TOKEN.md](FIRST_TOKEN.md) отдельно показан первый непустой фрагмент
SSE. Он может содержать только начало JSON; время первого видимого текста
на iOS в этом исследовании не измеряется.
