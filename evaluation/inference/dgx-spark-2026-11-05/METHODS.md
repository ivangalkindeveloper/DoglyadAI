# Как проверить результаты

Исследование выполнено на одном DGX Spark с GB10. Сравниваются MedGemma 4B,
MedGemma 1.5 4B и MedGemma 27B. Во всех опытах веса остаются BF16.
Версии библиотек, ревизии моделей и исходные команды сохранены в
`software.json`, `python-libraries.json`, `model-revisions.json` и
`runtime-before.json`. Это исследование производительности одной машины.
Оно не заменяет клиническую оценку качества.

## Состав доказательств

- `plan.json`: исходная матрица настроек и точные входы.
- `cache-pressure-plan.json`: дополнительная серия длинных ответов с большим KV-кешем.
- `prefix-plan.json`: проверка общего системного префикса и исправленная серия повторного исследования.
- `cases-*.json`: полные синтетические сценарии, JSON Schema и ожидаемые ответы простых цветовых проверок.
- `runs/*/command.json`: фактическая команда временного контейнера.
- `runs/*/container.log`: журнал движка, включая причины отказов при запуске.
- `0*/*/*/results.jsonl`: входы, ответы SSE, время, число токенов и счётчики движка.
- `06-shared-gpu-scheduling/results.jsonl`: очереди и ответы при общей нагрузке.
- `07-host-health/`: телеметрия, ICMP и проверка журнала ядра.
- `audit.json`: полнота данных, число запросов и результаты проверок.
- `verification.json`: состояние исходных контейнеров после эксперимента.
- `readiness-latest.json`: повторная проверка готовности перед публикацией и отсутствие оставшихся процессов эксперимента.
- `source-differences.json`: контрольные суммы локальных и фактически выполненных скриптов.
- `SHA256SUMS`: контрольные суммы опубликованных материалов, кроме самого файла контрольных сумм.

Событие `request` хранит склеенный текст ответа и измерения потока. Это не
побайтовый сетевой дамп. Время между фрагментами относится к непустым SSE-частям,
которые не обязаны соответствовать одному токену каждая. TTFT также измеряется
до первого непустого фрагмента; при JSON Schema это может быть только скобка.
Время первого видимого медицинского текста на iOS не измеряется.

Времена в таблицах — медианы измеряемых запросов или волн, как указано в заголовках.
Одна прогревочная волна исключается. Основные серии имеют три измеряемые волны;
дополнение KV-кеша — две. Отдельные проверки полных ответов и цветовых изображений
выполняются один раз на профиль. Основные сценарии протокола и диктовки повторяются
трижды. Малое число повторов не позволяет считать небольшую разницу доказанным
устойчивым выигрышем.

## Сопоставимость

Прямые запросы идут к частным адресам vLLM внутри DGX. Время не включает main
backend, App Check, Wi-Fi и интерфейс приложения. Рабочий inference backend
не меняется. Его лимиты очереди и 120 секунд на операцию сохраняются, хотя
исследовательский клиент допускает 600 секунд. Успешный длинный ответ в опыте
не доказывает, что рабочий API успеет вернуть его.

Кроме общей нагрузки в исследовании 06, две другие модели загружены и простаивают.
Изменяется только исследуемый профиль. Временные контейнеры используют тот же
образ и том с весами только для чтения. Они имеют защитный предел памяти:
30 GiB для моделей 4B и 85 GiB для 27B, без дополнительного swap контейнера.
Исходные рабочие контейнеры такого ограничения не имеют. Этот предел нужно
учитывать при интерпретации любого отказа памяти.

Независимые входы получают отдельный `cache_salt`. Общий salt используется
только в опытах повторного префикса. Обычные тесты скорости генерируют фиксированное
число токенов с `ignore_eos=true`; они не проверяют завершение медицинского ответа.
Полные ответы используют естественный EOS и лимит 2048 токенов. Клиент их не
обрезает по закрывающей скобке. Результаты JSON Schema и валидаторов main
сохраняются раздельно. Неудачные проверки не удаляются из знаменателей.

В `report-input-parity.json` проверено соответствие полных входов текущему
`PromptFactory`, схеме и параметрам main. В `cross-model-input-parity.json`
проверено совпадение сценариев между моделями, кроме их идентификаторов.
Файлы реализации валидаторов и конфигурации зафиксированы через SHA256 в
`validation-source-hashes.json`; версии локальных библиотек — в
`validation-libraries.json`. Публикация исходного кода — коммит `551536d`.

## Исправленная ошибка измерительного скрипта

В первой серии `application-cold/warm` метка запроса добавлялась к списку
текстовых блоков как последовательность символов. Chat template удалил пробелы
из этой метки. Исходные данные сохранены, а 18 измеряемых запросов исключены
из выводов. Основной системный текст и данные исследования не изменились.
Ошибка не затронула остальные тесты скорости или полные структурированные ответы.

Серия повторена под именами `application-corrected-*`. Сопоставление token IDs
с каноническими текстовыми блоками сохранено в `03-prefix-cache/`:
`content-format-parity.json` фиксирует исходное различие,
`corrected-content-format-parity.json` проверяет исправление. Это различие
входов измерительного скрипта, а не найденная ошибка рабочего приложения.

## Повторный анализ

`execution-source/` содержит точные Python-файлы с DGX. Их не заменяют более
поздние локальные исправления. В корне оставлены анализаторы и подготовленные
варианты запуска. В локальном `probe.py` исправлено добавление текстовой метки;
в `prepare.py` и `run.py` добавлена защита от перезаписи старой серии. Локальный
`observe.py` отличается удалением неиспользуемого импорта. Эти изменения не
переписывают фактически выполненный исходный эксперимент.

Из корня репозитория анализ можно повторить следующими командами. Окружение
Python должно содержать зависимости main backend, `jsonschema` и версии,
записанные в `validation-libraries.json`.

```sh
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-05/analyze.py
python3 evaluation/inference/dgx-spark-2026-11-05/analyze_host.py
python3 evaluation/inference/dgx-spark-2026-11-05/analyze_speculation.py
python3 evaluation/inference/dgx-spark-2026-11-05/write_tables.py
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-05/check_report_inputs.py
python3 evaluation/inference/dgx-spark-2026-11-05/audit.py
```

`analyze.py` остановится, если исходники валидаторов или конфигурация изменились.
Для воспроизведения нужно использовать зафиксированный коммит, а не обновлять
контрольные суммы под новые правила. Полный повтор GPU-опытов требует отдельной
свободной папки серии и проверки имён контейнеров, адресов и исходных настроек.
Скрипты управления контейнерами не предназначены для запуска на произвольном хосте.
