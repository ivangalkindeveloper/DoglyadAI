# Проверка порядка промпта и бюджета prefill

Дата: 7 ноября 2026 года. Доступ к `192.168.0.30` восстановлен: ping без потерь,
SSH работает. Ключ хоста совпал с сохранённым ключом прежнего адреса
`192.168.0.29`; подключение использует `HostKeyAlias` и строгую проверку ключа.
Результаты реальных замеров на DGX `spark-bfd6` собраны в [RESULTS.md](RESULTS.md).
Все три модели используют восемь слотов, N-gram 8 и исходные закреплённые образы.
На этапе измерений промпты приложения не менялись. После обсуждения результатов
в локальном коде применён только перенос шаблона; ID фото сохранены.
На сервер изменение не развёрнуто. Для сравнения бюджета выполнена попытка
временного переключения 2048 → 4096 → 2048 с сохранением остальных аргументов.
Кандидат 4096 не прошёл запуск 4B. Исходные команды восстановлены на всех моделях.

## 1. Порядок частей запроса

Подготовлены четыре варианта в отдельном эксперименте:

- `baseline`: текущий `PromptFactory` без изменений.
- `template_first`: существующий текст шаблона перенесён перед данными пациента.
- `stable_schema`: из **текстовой копии** JSON Schema удалён только `photoId.enum`.
  Поля, описания, обязательность, координаты и остальная структура сохранены.
- `combined`: оба изменения.

Во всех вариантах строгая схема в `response_format` остаётся побайтно
эквивалентной по содержимому текущей схеме. В ней сохранён `photoId.enum`.
Список ID фотографий остаётся в пользовательском тексте. Данные пациента,
описание исследования, шаблон и байты фотографий не теряются.

`prepare.py` вызывает текущие классы backend. Набор содержит 192 запроса:
три модели, два языка, наличие/отсутствие фотографии и шаблона, четыре варианта,
два вымышленных пациента. Для RU используется шаблон щитовидной железы,
для EN — мочевого пузыря из текущего каталога. Серое геометрическое изображение
проверяет обработку фотографий и ID; оно не является изображением УЗИ.

### Локальный результат

Длина общего текстового начала двух пациентов, в **символах Unicode**:

| Случай | Исходный | Только шаблон выше | Только постоянная текстовая схема | Оба изменения |
|---|---:|---:|---:|---:|
| RU, без фото и шаблона | 3443 | 3443 | 3443 | 3443 |
| RU, без фото, с шаблоном | 3443 | 4166 | 3443 | 4166 |
| RU, с фото, без шаблона | 4136 | 4136 | 5706 | 5706 |
| RU, с фото и шаблоном | 4136 | 4136 | 5706 | 6429 |
| EN, без фото и шаблона | 3346 | 3346 | 3346 | 3346 |
| EN, без фото, с шаблоном | 3346 | 3688 | 3346 | 3688 |
| EN, с фото, без шаблона | 3944 | 3944 | 5466 | 5466 |
| EN, с фото и шаблоном | 3943 | 3943 | 5466 | 5808 |

Результат одинаков для трёх моделей на этих входах. Это сравнение строк до
шаблона диалога и токенизации движка. Символы не равны токенам. Рост общего
начала не доказывает такой же процент ускорения или фактическое попадание в кеш.

Проверены 192 сохранения строгой схемы и текста пациента, 24 отказа схемы
для постороннего ID фотографии и 48 совпадений промптов development/production.
Фактура: [static-analysis.json](static-analysis.json), [cases.json](cases.json).

Вывод: порядок частей действительно ограничивает общий префикс. При наличии
разных ID фото перенос одного шаблона не увеличивает совпадение. Комбинация
изменений увеличивает общее начало. Скорость и валидность полных ответов
проверены отдельно; см. [результаты](RESULTS.md). В локальном коде применён
только перенос шаблона перед данными пациента.

## 2. Бюджет prefill

Найдена предыдущая проверка от 5 ноября:
[02-prefill-budget](../dgx-spark-2026-11-05/02-prefill-budget/README.md).
`audit_prefill.py` повторно вычислил медианы по исходным JSONL. Все 11 групп,
132 измеренных запроса, совпали с сохранённым отчётом. Прогрев исключён.
Каждый ответ содержит ровно 128 токенов; это технический тест планировщика.

Медиана времени полного технического ответа, секунды:

| Модель | 2048 | 4096 | 8192 |
|---|---:|---:|---:|
| MedGemma 4B | 8,49 | 8,67 | 8,60 |
| MedGemma 1.5 4B | 8,58 | 8,66 | 8,72 |
| MedGemma 27B | 52,77 | 53,96 | Не запустилась |

У 27B максимум паузы SSE вырос с 1,55 до 2,99 секунды при переходе 2048 → 4096.
Для бюджета 8192 движок потребовал 8,76 GiB KV-кеша вместо выделенных 8 GiB.
Это отказ проверки конфигурации при запуске, не OOM хоста.

Условия прежней серии: четыре одновременных входа около 8000 токенов,
отдельный `cache_salt` на запрос, без N-gram. Текущий профиль имеет восемь слотов
и N-gram 8. Поэтому эти результаты поддерживают сохранение 2048, но не заменяют
новое сравнение текущего режима на полных отчётах и смешанной нагрузке.
Фактура повторной проверки: [prefill-audit.json](prefill-audit.json).

## Воспроизведение

Сохранённые `cases.json` и `source-hashes.json` фиксируют код до применения
перестановки. `prepare.py` читает текущий код, поэтому его повторный запуск
после изменения `PromptFactory` создаст другой `baseline`. Для воспроизведения
сравнения используйте сохранённые случаи или исходную версию файлов с указанными
хешами. Не перезаписывайте архивные случаи текущим генератором.

На Mac из корня репозитория:

```bash
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-07-prefix-prefill/prepare.py
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-07-prefix-prefill/audit_prefill.py
```

`run_prefix.py` предназначен для DGX. Он получает приватные адреса уже работающих
контейнеров через Docker, проверяет отсутствие активных запросов и ничего
не меняет в контейнерах. Все три модели остаются загружены. Запросы выполняются
по одному; это проверка отдельного запроса, не одновременной нагрузки 8/8/8.

Каждая пара пациентов получает отдельный salt. Первый запрос имеет холодный
кеш, второй использует то же пространство кеша. Соль не меняется между
пациентами пары. Порядок вариантов меняется на обратный во втором повторе.
Счётчик завершений должен увеличиться ровно на один после каждого запроса.
Сохраняются полный ответ, token IDs, TTFT и счётчики кеша. При посторонней
нагрузке или незавершённом ответе скрипт останавливается с сохранением фактуры.

Пример из каталога исследования на DGX:

```bash
python3 run_prefix.py --models 4b 15-4b 27b --scenarios ru-photo1-template1 --repetitions 2 --output prefix-results.jsonl
```

Это 48 генераций, включая первые запросы пар, и отдельный прогрев. Дополнительно
выполнены 144 технических запроса для TTFT и 24 полных запроса RU/EN без фото
с шаблоном. Строгая схема и валидаторы содержания/измерений main проверяются
на Mac:

```bash
.venv311/bin/python evaluation/inference/dgx-spark-2026-11-07-prefix-prefill/validate.py PATH_TO_RESULTS.jsonl
```

Внутренний тест движков не заменяет запрос из приложения с App Check. Защита
API не меняется. `probe.py` скопирован без изменений из исследования
`dgx-spark-2026-11-05-ngram-capacity`. Исторические результаты не изменены.

## Проверки кода

- 92 существующих теста main backend по отчётам, замечаниям и содержанию прошли.
- Ruff для файлов этого исследования прошёл.
- Общий `make check-architecture` нашёл 13 нарушений `swift.view-fragment`
  в Swift-файлах вне изменений этой проверки. Они не исправлялись в этой задаче.
- Результаты новых генераций на GPU сохранены, включая отказы. Проверка
  медицинской точности изображений не выполнялась; корректная JSON Schema
  сама по себе её не гарантирует.

Полнота проверки и команды сохранены в [checks.json](checks.json).
