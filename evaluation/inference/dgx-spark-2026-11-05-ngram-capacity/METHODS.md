# Параллельность и KV-кеш после включения N-gram 8

Цель: закончить проверку 8/8/8 запросов и KV-кеша 27B, затем применить
подходящую конфигурацию на DGX. Квантование в работу не входит.

## Сравниваемые варианты

| Вариант | Слоты 4B / 1.5 4B / 27B | KV-кеш, GiB |
|---|---|---|
| baseline | 4 / 4 / 4 | 4 / 4 / 8 |
| seq8 | 8 / 8 / 8 | 4 / 4 / 8 |
| seq8-kv12 | 8 / 8 / 8 | 4 / 4 / 12 |

При необходимости отдельно проверяется `seq4-kv12` с четырьмя слотами и
12 GiB для 27B. Везде сохраняются N-gram 8, BF16, ревизии моделей, образ vLLM,
контекст 16384, prefill 2048, компиляция, CUDA Graphs и prefix caching.

Во время измерений canonical-профиль и лимиты inference API сохраняются.
Тестовые Compose overrides меняют только команды нужных движков.
При ошибке контроллер восстанавливает исходный профиль. Финальное применение
делается отдельно, после сравнения результатов, с согласованными лимитами API.

## Метод и границы

- Все три модели постоянно загружены. Запросы к разным моделям поступают
  одновременно через барьер потоков.
- Серии: прогрев 4/4/4, один запрос на каждую модель, два измерения 4/4/4,
  два измерения 8/8/8, смешанная серия 8/8/8. Смешанная серия содержит отчёты
  RU/EN, диктовку, противоречивые данные и цветные синтетические изображения.
- Сборщик ждёт полного ответа и естественного завершения SSE. Входы и схемы
  скопированы без изменений из предыдущего исследования; их хеши сохранены.
  Ключи prefix-кеша различаются для всех запросов.
- Отдельный технический тест: четыре и восемь запросов только к 27B,
  около 15000 входных токенов и ровно 256 выходных. Здесь `ignore_eos=true`
  и окончание по лимиту намеренные. Это тест памяти/планировщика, не полный
  отчёт и не подтверждение качества модели. Остальные модели загружены без
  генерации. Payload взят из предыдущего исследования KV-кеша.
- Прямой запрос к закрытому движку имеет диагностический предел 600 секунд.
  Каждое превышение рабочих 120 секунд отмечается отдельно. Завершение за
  600 секунд не означает успех через штатный inference API.
- Восемь клиентов у исходного движка с четырьмя слотами показывают очередь
  самого vLLM. Штатный API сейчас допускает 4 выполняемых и 1 ожидающий запрос
  на модель; он не примет все восемь одновременно. Такие результаты не
  описывают текущую пропускную способность публичного приложения.
- У baseline encoder-кеш изображений уже прогрет предыдущими проверками.
  У пересозданных движков первая смешанная серия обрабатывает изображения
  впервые. Обычные текстовые серии сопоставимы; смешанная серия также проверяет
  стартовую обработку изображений у кандидатов.
- Метрики RAM, температуры, swap, активных/ожидающих запросов и KV-кеша
  собираются каждые пять секунд. Отдельно сохраняются журналы NVIDIA за период
  каждого варианта. Исходная запись `NV_ERR_NO_MEMORY` от 22:15:01 MSK относится
  к предыдущему исследованию и не считается новой ошибкой этой серии.

## Критерии выбора

Выбор учитывает время полного ответа, долю запросов до 120 секунд, TTFT,
полноту JSON, main-валидацию, запас RAM и новые ошибки GPU. Ускорение завершения
всей очереди само по себе не оправдывает рост числа таймаутов обычных отчётов.
Ошибки медицинского содержания не скрываются за успешным JSON; отдельные
различия sampling не доказывают клиническую эквивалентность или регрессию.

Фактура хранится по вариантам. `controller.py` управляет последовательным
запуском, `experiment.py` задаёт нагрузку, `probe.py` собирает SSE,
`observe.py` снимает состояние. Запросы содержат только синтетические данные.
