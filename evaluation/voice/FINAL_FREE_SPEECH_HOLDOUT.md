## Как проходил замер

```text
Новый готовый текст + заранее заданные ожидаемые поля
    → неизменный промпт main + действующая JSON Schema
    → google/medgemma-4b-it во внутренней vLLM на существующей GPU VM
    → неизменная проверка значений, цитат, типов и принадлежности полю из main
    → сравнение итоговых предложений с эталоном
```

Параметры: `temperature=0`, `max_tokens=2048`, два параллельных запроса. До трёх попыток разрешены только при транспортной или серверной ошибке. Семантических повторов и выбора лучшего ответа нет. **Каждый из 40 случаев завершился с первой попытки**, `finishReason=stop`; ошибок запроса, обрезаний и ошибок валидации JSON не было.

Верное поле — итоговое значение совпадает с эталоном. Для текста прежний оценщик игнорирует регистр, пробелы и пунктуацию, сохраняя слова и числа; для клинического текста также допускается `е/ё`. Числа сравниваются по числовому значению, дата — в ISO. Полностью точная форма требует всех ожидаемых значений и отсутствия лишних полей. Отсутствующие поля учитываются при проверке формы, но не увеличивают знаменатель «верных полей». Строгая и эквивалентная метрики в этом прогоне совпали.

Проверялся серверный разбор **готового текста**, включая обработку main. ASR, Foundation Models, клиентское применение формы и защищённый HTTP-путь main → inference с действительным App Check здесь не измерялись. Внутренняя генерация выполнялась на GPU VM; защита приложения не отключалась. Медиана показывает время запроса генерации, а не задержку полной функции на iPhone.

Однако она пропустила три приведённых выше лишних клинических поля как `questionable`: одной дословной цитаты недостаточно, чтобы доказать принадлежность текста нужному разделу.

Рабочий код и промпты **не исправлялись** на этих примерах. Дальнейшая работа по найденным ошибкам потребует отдельного изменения и нового независимого контроля; повторная оценка этого набора после настройки будет регрессионной.
