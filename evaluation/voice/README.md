# Оценка медицинской речи

Проект сравнивает распознавание речи (ASR), извлечение данных из транскрипта
и заполнение формы исследования. Медицинские примеры называются **тесткейсами**.
Текстовое совпадение и проверенная врачом клиническая корректность — разные метрики.

## Врачу

Откройте [Медицинские тесткейсы](doctor/index.html) в браузере и выберите набор.
[Инструкция врачу](doctor/README.md) описывает проверку текста, аудио и полей формы.

- **Сохранить всё / Сохранить тесткейс** — сохранить текущее состояние ответов
  в браузере. При следующем открытии того же набора оно восстановится автоматически.
- **Скачать копию ответов** — получить файл для передачи разработчику или резервного хранения.
- **Загрузить ответы из файла** — продолжить работу с сохранённой копией.

Готовые пакеты и их аудио находятся в `build/voice-eval/medical-review-current-ru/`
и `build/voice-eval/medical-review-pilot-ru/`. Для передачи врачу копируется вся
папка пакета. Нынешняя страница проверяет существующие тесткейсы; запись нового
тесткейса голосом пока не реализована в интерфейсе.

## Структура

| Каталог | Содержимое |
|---|---|
| `doctor/` | Страница врача, инструкция и сборка пакетов проверки |
| `datasets/` | Генераторы, контракты тесткейсов, проверки разметки и `fixtures/` |
| `audio/` | Озвучивание, WAV, акустические варианты и Swift-утилиты в `swift/` |
| `runners/` | Запуски на iPhone/Mac/сервере, импорт и воспроизведение ответов |
| `scoring/` | WER, нормализация, оценка извлечения, клинических фактов и действий |
| `analysis/` | Сравнения инструментов, диагностика ошибок и сборка отчётов |
| `docs/` | Протокол, команды; исторические отчёты в `docs/reports/` |
| `results/` | Зафиксированные результаты, происхождение и контрольные суммы |
| `tests/` | Проверки инструментов оценки и страницы врача |

Общие константы и функции остаются в `common.py`. WAV, веса моделей, кеши,
собранные утилиты и рабочие результаты хранятся в `build/voice-eval/`.

## Основные команды

Все команды выполняются из корня репозитория. Каталоги новых результатов
должны быть новыми: инструменты не перезаписывают зафиксированные измерения.

Проверить черновой корпус:

```bash
.venv311/bin/python -m evaluation.voice.datasets.clinical_corpus \
  evaluation/voice/datasets/fixtures/clinical_pilot_v2.json
```

Подготовить переносимый пакет врачу с аудио:

```bash
.venv311/bin/python -m evaluation.voice.doctor.prepare_medical_review \
  evaluation/voice/results/2026-10-25-asr-extraction/corpus-final.json \
  --locale ru --copy-audio --output build/voice-eval/medical-review-new-ru
```

Пересчитать зафиксированные ответы без запуска моделей:

```bash
.venv311/bin/python -m evaluation.voice.scoring.rescore_baseline \
  evaluation/voice/results/2026-10-25-asr-extraction \
  --output build/voice-eval/asr-matrix-2026-10-24/score-new
```

Подготовить одинаковые входы для парсеров:

```bash
.venv311/bin/python -m evaluation.voice.runners.parser_replay prepare \
  evaluation/voice/datasets/fixtures/clinical_pilot_v2.json \
  --output build/voice-eval/parser-jobs-new
```

Проверить инструменты:

```bash
.venv311/bin/python -m pytest evaluation/voice/tests -q
.venv311/bin/ruff check evaluation/voice
```

Полные параметры и изоляция этапов описаны в
[протоколе оценки](docs/EVALUATION_PROTOCOL_V2.md). Подробные команды прежних
экспериментов — в [workflows.md](docs/workflows.md). Карта перенесённых файлов
и порядок проверки — в [плане организации проекта](docs/reorganization-plan.md).

## Результаты и ограничения

[Исходная матрица 24–25 октября](results/2026-10-25-asr-extraction/) и
[пересчёт v2.1](results/2026-10-25-rescored-v2.1/) сохранены с контрольными суммами.
Исторические JSON, CSV и снимки исходников описывают свои запуски; старые пути
внутри этих артефактов не переписываются. Модули Python используют новые пути.

Нынешние аудио синтетические. 64 текстовых тесткейса нового пилота ещё ожидают
медицинской проверки. Эти результаты не устанавливают качество на речи врачей
во время настоящих исследований. Отказы и пропавшие результаты сохраняются
в знаменателях, а непроверенная клиническая эквивалентность не считается успехом.
