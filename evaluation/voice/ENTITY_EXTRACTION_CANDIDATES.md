# Извлечение полей из транскрипта: кандидаты

Проверено 4 октября 2026 года. Это исследование возможностей моделей, а не измерение их точности на диктовке Doglyad. Для всех кандидатов нужен одинаковый тест на сохранённых WhisperKit-транскриптах EN/RU, трёх стилях речи, чистом и шумном звуке. Эталон и код оценки уже находятся в `evaluation/voice/`.

## Контракт результата

Каждый модельный путь возвращает массив объектов с `field_id`, `value`, `evidence` и `accuracy`. Идентификаторы полей записываются в snake_case. Номер исследования остаётся строкой, чтобы не потерять ведущие нули; пол (`male`/`female`), дата (`YYYY-MM-DD`) и текстовые поля также строки. Рост и вес — JSON-числа. `evidence` — непрерывный дословный фрагмент входного транскрипта. `accuracy` равен `full` или `questionable` и отражает однозначность извлечения **из данной строки**, а не надёжность самого ASR. Поле `full` нельзя считать измеренной вероятностью правильности: в тестах отдельно считаются неверные значения с этой меткой.

У Foundation Models элемент `@Generable` содержит строковое `value`: Swift guided generation требует статический тип свойства. Адаптер преобразует рост и вес в числовой `VoiceFieldValue` перед передачей форме. MLX и GPU генерируют JSON-число сразу. Серверный HTTP-ответ оборачивает проверенный массив в `proposals` вместе с `rejectedFieldIds`, чтобы клиент видел отброшенные поля.

В продукте Foundation Models остаётся первым модельным путём при доступности для языка и устройства. Детерминированные метки и явные факты пока предшествуют вызову модели; их качество оценивается отдельно.

## Что имеет смысл измерить

| Кандидат | Возможности по первичному источнику | Ограничение для нашей задачи |
|---|---|---|

Может потребовать адаптировать запрос к собственному формату шаблона NuExtract. |

| [GLiNER2.5 multi](https://github.com/fastino-ai/GLiNER2) | Компактная мультиязычная модель извлечения фрагментов и структур, может работать на CPU и возвращать позиции фрагментов в исходном тексте. | Позиции дают сильный `evidence`, но преобразование даты, пола, роста и веса в типизированное значение остаётся отдельной логикой. Поддержку русского медицинского текста нужно измерить. |

[Apple Foundation Models](https://developer.apple.com/documentation/foundationmodels/generating-swift-data-structures-with-guided-generation) уже даёт управляемую генерацию структур на устройстве и остаётся приоритетом при доступности. [MedGemma-4B-IT](https://huggingface.co/google/medgemma-4b-it) измерена как серверная базовая линия на готовом тексте: [результаты](MEDGEMMA_IDEAL_TEXT_BASELINE.md) показали 0 строго точных форм из 372, несмотря на часть верных отдельных полей. MLX/Qwen2.5-1.5B использовался для исторического сравнения; текущий путь при недоступной Foundation Models обращается к серверной MedGemma, веса MLX в приложении отсутствуют.

## Порядок проверки

1. Подать одним и тем же кандидатам одинаковые сохранённые WhisperKit-строки и одинаковый контракт. Запускать GPU-модели последовательно на существующей VM, без нового сервиса.
2. Считать точность каждого поля, полностью точные формы, ложные поля, ошибочные `full`, пропуски, время ответа и память. Отдельно смотреть сторону, отрицание, дату, номер и единицы измерения.
3. Сначала настроить промпт на открытых случаях, затем выбрать кандидата на новом независимом наборе. Не объявлять победителем модель по её собственному опубликованному бенчмарку: он не измеряет нашу диктовку.

Исходный текст пациента и аудио не должны попадать в внешние API или логи. Для серверных кандидатов используется собственная GPU VM и текущий путь через main backend.
