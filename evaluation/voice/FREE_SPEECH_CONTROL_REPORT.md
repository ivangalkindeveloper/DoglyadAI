# Свободная диктовка и рабочий выбор разбора — 8 октября 2026

## Рабочая схема iOS

1. Аудио записывается и расшифровывается локально через **WhisperKit Turbo** (`large-v3-v20240930_626MB`). При первом открытии шторки видны проверка, скачивание и загрузка модели; запись доступна после готовности модели.
2. Для каждой законченной диктовки проверяется доступность **Foundation Models**, включая поддержку языка текста. Доступная модель используется первой, даже для частичной формы.
3. Если Foundation Models недоступна, готовый текст и ID типа исследования отправляются через `DoglyadNetwork` в main: `POST /v1/ultrasound/parse_dictation`. Main выбирает модель из `voice_form_parsing.json`: в development и production это **`google/medgemma-4b-it`**. ID разрешается через существующую карту inference-эндпоинтов. Inference вызывает свою локальную vLLM.
4. Audio не отправляется на backend. MLX/Qwen больше не выбирается рабочей фабрикой разбора; отдельная реализация сохранена для исследований и исторических замеров. Ошибка доступной Foundation Models не запускает вторую генерацию на сервере; отменённый запрос тоже не переключается на другой провайдер.
5. Оба пути возвращают предложения с `field_id`, `value`, `evidence`, `accuracy`. Клиент проверяет цитаты, типы и противоречия. Отсутствующее поле не изменяется; сохранением и применением формы владеет Scan.
6. Для законченной WhisperKit-диктовки проверенные `full` без предупреждений и с единственной исходной цитатой применяются автоматически. `questionable`, предупреждения, изменённый текст или незаконченная запись требуют проверки. WhisperKit не предоставляет откалиброванную уверенность каждого слова: `full` означает решение проверки извлечения из текста, а не доказательство правильности распознавания аудио.

Выбор провайдера находится в `DictationParseRouter`, вызов — в `ScanSpeechViewModel`. Голосовая кнопка больше не скрывается из-за отсутствия локальной модели: доступен серверный разбор. App Check сохраняется на main и inference, токен передаётся неизменным существующим HTTP-клиентом.

## Отдельный контроль свободной речи

Созданы 32 ранее не использованных RU/EN-текста: по 16 на язык, **144 ожидаемых поля**. Здесь новые имена/даты/номера, длинные отрицательные описания, естественный порядок фрагментов, описания без вводной метки, жалобы в конце, частичные формы, только данные пациента и только клинические поля. Тексты — законченные пунктуированные строки. Некоторые естественные фразы содержат обозначения «Жалобы», «Рост», «Вес»; последовательного заполнения полного шаблона не требуется.

Значения явно заданы в [free_speech_control.json](fixtures/free_speech_control.json), независимо от рабочих парсеров. Входы, эталоны, промпты, JSON Schema и исходники обработки сохранены до ответов. Прогон сделан на существующей MedGemma, без замены модели, `temperature=0`, 2048 выходных токенов, два параллельных запроса. До трёх попыток разрешены только для транспортных/серверных ошибок. Семантические ошибки не перегенерируются и лучший ответ не выбирается.

Все 32 генерации завершились без обрезания и транспортных ошибок. Точная форма требует всех ожидаемых значений и отсутствия лишних полей. Строгое сравнение допускает регистр, пробелы и пунктуацию, сохраняя все слова и числа; строгая и эквивалентная метрики здесь совпадают.

Причины ошибок и исправления:

- Жалобы в конце строки: модель теряла последующее отрицание или оставляла вводную фразу пациента. Теперь явно ограниченный клинический раздел сохраняется целиком. Когда описание дано без заголовка после жалоб, его единственная дословная модельная цитата используется как граница. Перекрывающаяся цитата не доказывает границу. Свободные разделы остаются `questionable`.
- В тексте только с данными пациента модель добавляла «Ультразвуковое исследование» либо копировала все данные в описание. Клиническое значение должно быть поддержано словами исходной цитаты; блок, целиком покрытый независимо выделенными данными пациента/жалобами, не становится описанием исследования.
- Проверка границ по прежним 60 текстам обнаружила включение описания без метки в последние жалобы. Исправление использует дословную цитату описания, без списка названий органов. Старый набор вновь проходит 60/60 форм.
