# Три набора проверки голосового заполнения

Каждый набор содержит 124 вымышленных случая: 31 тип исследования × 2 языка ×
полная/частичная диктовка. Эталонные поля известны до озвучивания.
`guided-format` повторяет названия и порядок полей из подсказки в шторке,
включая поле «пол». `reordered-format` сохраняет названия полей, но начинает
с описания и меняет порядок остальных. `freeform-development` содержит
связную речь без названий полей. Частичная диктовка включает 2 поля в точном
формате и 4 поля в двух других наборах. Для каждого случая подготовлены
чистый и шумовой WAV с проверяемым SHA-256.

Метрика «точная форма» требует совпадения **всех** произнесённых полей и
отсутствия заполнения непроговорённых. Знаменатель включает ошибки и пропуски
разбора. WER сравнивает транскрипт с текстом, поданным синтезатору; звук не
размечался человеком. Прямой разбор эталонного текста на iOS Simulator дал
**124/124 в каждом из трёх наборов**.

Для аудиопроверки WAV распознавал системный Apple DictationTranscriber **на
Mac**, после чего его строка подавалась в тот же iOS-парсер на симуляторе.
Все 124 WAV распознаны в каждом из шести прогонов. WER усреднён по 62
файлам языка после нормализации записи чисел и единиц.

| Набор / аудио | WER en / ru | Полная форма en / ru | Частичная форма en / ru |
|---|---:|---:|---:|
| Точный формат, чистое | 18,70% / 6,36% | 0/31 / 14/31 | 0/31 / 13/31 |
| Точный формат, шумовое | 30,01% / 4,57% | 0/31 / 24/31 | 0/31 / 20/31 |
| Формат без порядка, чистое | 12,99% / 3,22% | 0/31 / 9/31 | 3/31 / 27/31 |
| Формат без порядка, шумовое | 15,42% / 2,20% | 0/31 / 25/31 | 1/31 / 27/31 |
| Свободная речь, чистое | 24,00% / 7,42% | 0/31 / 0/31 | 0/31 / 0/31 |
| Свободная речь, шумовое | 36,52% / 7,83% | 0/31 / 0/31 | 0/31 / 0/31 |

Шумовой вариант случайно улучшил русскую диктовку по формату в этом
синтетическом наборе; это не свойство реального кабинета. Низкая доля точных
форм после ASR не противоречит 124/124 при прямой передаче текста: ошибки
распознавания меняют имена, числа, метки и медицинские слова. Эти цифры нельзя
приписывать SpeechAnalyzer на iPhone или записи через микрофон.

Исходные отчёты находятся в `build/voice-eval/audio/<mode>/asr-{clean,noisy}-report.json`,
где `<mode>` — `guided-format`, `reordered-format` или `freeform-development`.
Разбор эталонного текста — в `build/voice-eval/ios-candidate-text-diagnostic-<mode>-clean/summary.json`.
Разбор ASR-строк — в `build/voice-eval/ios-candidate-text-asr-replay-*/summary.json`;
там же доступны счётчики отдельно по языку и полной/частичной диктовке.
Каталог `build/` исключён из Git. Команды для воспроизведения приведены в
[README.md](README.md).

## Проверка на физическом iPhone — 3 октября 2026 года

Устройство: iPhone 17, iOS 26.6.2. Все 744 синтетических WAV (три набора ×
чистый/шумовой звук × 124 случая) прошли **SpeechAnalyzer на iPhone** с
контекстными подсказками и словарной коррекцией: 744/744 завершились
транскриптом. Шумовой профиль имеет SNR 25 дБ. Это распознавание файла,
микрофон и реальная речь врача не участвовали.

Исправленные транскрипты затем отдельно поданы в iOS-парсер. Оба варианта
`guided-format` и `reordered-format` разобраны **на том же iPhone**. Для
`freeform-development` полный разбор на iPhone не завершился за 50 минут;
CoreDevice не позволил извлечь промежуточный отчёт. Оба варианта свободной
речи разобраны **на iOS Simulator** из транскриптов iPhone. Его локальная
модель может отличаться по доступности и результату от модели на устройстве;
эти строки нельзя считать полным измерением цепочки на iPhone.

Во всех ячейках «полная/частичная форма» знаменатель 31 на язык. Для точного
формата «частичная» соответствует `missing_demographics` (произнесены два
поля); для остальных наборов — `partial` (четыре поля). «Ошибки без
предупреждения» — число предложенных неверных значений полей, для которых
парсер не выставил предупреждение. Оно суммируется по случаям, а не является
числом неверных форм.

На iPhone быстрый разбор диктовки с метками использован в 123/124 чистых и
93/124 шумовых случаях точного формата, а также в 121/124 случаях каждого
варианта без порядка. Остальные случаи обрабатывала локальная модель. Для
шумового точного формата 95-й перцентиль времени разбора — 20,36 секунды;
для остальных трёх форматных прогонов — около 0,03 секунды или меньше. На симуляторе
свободная речь вернула `explicitFacts` во всех 124 чистых и 123 шумовых
случаях. Один шумовой английский случай
`freeformDev-en-arteriesOfTheUpperExtremities-01` стабильно завершился ошибкой
Foundation Models / SensitiveContentAnalysisML; повторение полного прогона
дало 61/62 успешных английских разборов снова.

Резервный `SFSpeechRecognizer` проверен на двух вариантах точного формата:
каждый из 248 файлов получил системную ошибку `Siri and Dictation are
disabled`, поэтому его WER и качество формы здесь не измерены. Для остальных
наборов выполнялся основной путь SpeechAnalyzer с подсказками.

Итог: цели высокого качества пока не достигнуты. При точном формате даже
русская чистая диктовка даёт лишь 32/62 полностью верных формы; английская —
0/62. В свободной речи точных форм нет ни в одном из двух вариантов на
симуляторе. Чаще всего точному совпадению мешают описание исследования,
жалобы и имя пациента. Неожиданное улучшение русских показателей от
синтетического шума нельзя трактовать как улучшение на реальных записях.
Без проверки микрофона и речи врачей эти числа характеризуют только текущий
синтетический набор.

Сырые результаты ASR, его `summary.json` и транскрипты для повтора находятся
в `build/voice-eval/ios-candidate-device-{asr-only,confidence-only-asr-only}-<mode>-<variant>/`.
Результаты разбора — в каталогах `build/voice-eval/ios-candidate-{device-}text-asr-replay-*/`;
`runner.json` в каждом каталоге указывает физическое устройство или
симулятор, а `summary.json` содержит показатели по языкам, сценариям и полям.
