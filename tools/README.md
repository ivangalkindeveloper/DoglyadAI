# Harness агентов

`make sync-harness` обновляет локальные навыки, hooks и MCP из `harness/`.
`make check-harness` проверяет соответствие исходникам.
Структура, личные настройки и обработка конфликтов описаны в
[руководстве harness](../harness/README.md).

`make check-architecture` запускает быстрые проверки Swift и Python из
`harness/checks/`. После правок агентом их вызывает общий `PostToolUse`-хук.
Правила, ограничения и ручной запуск описаны в руководстве harness.

# Форматирование Swift

## Команды

```sh
make format-ios
make lint-ios
```

`format-ios` применяет SwiftFormat, затем правила структуры и переносов через SwiftSyntax, затем выравнивает результат SwiftFormat. `lint-ios` проверяет эти правила без изменения файлов. Общая команда `make format` дополнительно форматирует оба Python backend.

Даже один аргумент переносится на отдельную строку; после последнего ставится запятая:

```swift
let result = parse(
    text: transcript,
    locale: locale,
)

func stop(
    completion: DSpeechCompletion,
) { /* … */ }
```

Правило действует на вызовы, параметры объявлений функций/инициализаторов, индексы, вызовы макросов и обычные списки аргументов атрибутов. Пустые списки, типы функций и содержимое строк, включая интерполяции, сохраняются: перенос внутри строки может изменить её значение или сделать Swift-код недопустимым. Специальный синтаксис атрибутов вроде `@available` тоже сохраняется.

В классах сначала идут хранимые поля, затем инициализаторы, затем вычисляемые свойства и геттеры/сеттеры (включая `subscript`), затем методы. Такой же порядок действует внутри каждого блока `extension`. Между непустыми группами, отдельными инициализаторами и методами обязательна пустая строка, в том числе у пустых реализаций. Наблюдатели `willSet`/`didSet` остаются в группе хранимых полей. Относительный порядок хранимых полей, инициализаторов, вычисляемых свойств и методов внутри каждой группы сохраняется. Непустое тело инициализатора всегда занимает несколько строк. Комментарии перемещаются вместе со своими объявлениями. Блоки с условными членами `#if` не переставляются, чтобы сохранить порядок инициализации свойств; их порядок нужно поддерживать вручную.

Между соседними хранимыми полями классов и структур пустых строк нет. Это относится также к полям с замыканиями, property wrappers и комментариями. Расстояние между объявлениями задаёт SwiftSyntax; правило SwiftFormat `blankLinesBetweenScopes` отключено, чтобы инструменты не возвращали удалённые строки.

Accessibility-поля, параметры инициализаторов и аргументы вызовов идут последними. Это проверяет `make check-architecture`. Передавайте содержимое `ViewBuilder` явно через `content:`, если после него нужны accessibility-аргументы. Блокировку задавайте через `isDisabled` каждого интерактивного компонента; `.disabled(...)` реализуется внутри дизайн-системы.

Генератор `test/scripts/catalog.py` форматирует `RegressionScreens.swift` и `RegressionRepositoryAdapters.swift` через ту же функцию `format_swift_source`. Исправляйте генератор, а не сгенерированные файлы; `catalog.py --check` проверяет также их форматирование.

Между соседними вьюхами, подвьюхами и блоками условной вёрстки ставится одна пустая строка. Правило действует и во вложенных контейнерах. Цепочка модификаторов остаётся рядом со своей вьюхой. Обычные инструкции в обработчиках `action`, `onAppear`, `onChange`, `task` и других событий этим правилом не разделяются.

Непустые тела функций, инициализаторов, аксессоров, условий и замыканий занимают несколько строк. Первая инструкция идёт после открывающей скобки или сигнатуры замыкания с `in`. Закрывающая скобка находится на отдельной строке. Пустые тела могут оставаться в одну строку. `wrapConditionalBodies` включён также в `ios/.swiftformat`.

## Как устроена проверка

- `ios/.swiftformat` задаёт общие правила, Swift 6.4, языковой режим Swift 5 и SwiftFormat ≥ 0.58.7.
- `format_ios.py` выбирает исходники, запускает инструменты и кэширует собранное правило в игнорируемой папке `build/swift-formatting/`.
- `format-swift-arguments.swift` разбирает синтаксическое дерево, упорядочивает члены классов и расширений, добавляет переносы/запятые и разделяет соседние вьюхи пустыми строками. Перед записью проверяет синтаксис всех файлов и сохранность токенов и комментариев, кроме запятых; перестановка допускается только для целых объявлений внутри класса или расширения.
- Используются SwiftParser и SwiftSyntax выбранного Xcode через `xcrun`. Дополнительный SPM-пакет не скачивается. Нужны установленный Xcode и SwiftFormat.
- Папки `ios/Config`, `ios/Firebase`, `ios/DoglyadNeuralModel/Resources` и каталоги сборок исключены через `.swiftformat`.

Регрессионные проверки правила:

```sh
python3 -m unittest discover -s tools/tests -p 'test_format_ios.py' -v
```

Они проверяют одиночные и вложенные вызовы, порядок членов классов и расширений, различение хранимых полей с наблюдателями и вычисляемых свойств, пустые строки между методами, оформление инициализаторов, условные члены, комментарии, литералы, макросы, атрибуты, индексы, повторное форматирование и компиляцию примера в языковом режиме Swift 5.

# Форматирование Python backend

```sh
make format-backend
make lint-backend
```

Нужны Python 3.11 и зависимости из `backend/main/requirements-dev.txt` или `backend/inference/requirements-dev.txt`. Make предпочитает `.venv311`; другой интерпретатор можно задать через `BACKEND_FORMAT_PYTHON`, Ruff — через `RUFF`.

Каждый параметр функции, метода или конструктора и каждый аргумент вызова занимает отдельную строку, включая одиночный аргумент и `self`/`cls`:

```python
class Client:
    def __init__(
        self,
        timeout: int,
    ) -> None:
        self.timeout = timeout

client = Client(
    timeout=30,
)
```

`format_python.py` обходит все `.py` под `backend/`, включая тесты, скрипты и миграции. `python_argument_transformer.py` через LibCST добавляет завершающие запятые в списки параметров и аргументов; затем Ruff расставляет переносы и отступы. В обоих `pyproject.toml` закреплено `skip-magic-trailing-comma = false`. У Ruff нет отдельной настройки для обязательного переноса даже одного аргумента, поэтому обычный `ruff format` не заменяет эту команду.

Пустые списки остаются `()`. Значения строк, включая выражения f-строк, сохраняются: их свободный перенос несовместим с Python 3.11. Параметры lambda, наследование классов и индексы сохраняют обычный синтаксис; вызовы в теле lambda форматируются. Неявный генератор в вызове получает скобки перед добавлением запятой, сохраняя тип аргумента.

Перед записью всего набора проверяются синтаксис Python 3.11, идентичность AST и комментариев и обязательные переносы. Ошибка в любом исходнике прерывает обработку до записи изменений. Каждый измененный файл заменяется атомарно с сохранением прав, включая исполняемый бит. Секреты, виртуальные окружения, симлинки и каталоги сборок исключены. `--check` ничего не записывает и возвращает ненулевой код, если форматирование необходимо. CI выполняет ту же проверку отдельно для обоих backend.

Можно указать отдельные файлы или каталоги:

```sh
.venv311/bin/python tools/format_python.py backend/main/app
.venv311/bin/python tools/format_python.py --check backend/inference
.venv311/bin/python -m unittest discover -s tools/tests -p 'test_format_python.py' -v
```

Регрессионные проверки покрывают вложенные вызовы, параметры разных видов, декораторы, генераторы, строки, комментарии, повторный запуск, режим проверки, права файлов, исключения и отказ без частичной записи при ошибке синтаксиса.
