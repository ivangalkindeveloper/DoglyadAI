Политика конфиденциальности

Дата вступления в силу: 1 августа 2026 г.
Последнее обновление: 16 августа 2026 г.

Настоящая Политика конфиденциальности (далее — «Политика») определяет категории данных, обрабатываемых мобильным приложением Догляд AI (далее — «Приложение»), цели и порядок их обработки, места их хранения и применимые сроки хранения. Используя Приложение, вы подтверждаете, что ознакомились с настоящей Политикой и соглашаетесь с её положениями.

1. Ответственный за обработку данных

Приложение разработано и поддерживается Иваном Галкиным, индивидуальным разработчиком (далее — «Разработчик», «мы»). По вопросам, связанным с обработкой данных, вы можете обратиться по адресу: doglyadapp@gmail.com.

Для целей GDPR и аналогичного законодательства роли сторон распределяются следующим образом:

  • в отношении данных пациентов контролёром (controller) является медицинский специалист или медицинская организация, вносящие соответствующие данные в Приложение; Разработчик выступает исключительно в качестве обработчика (processor) и действует по поручению медицинского специалиста;
  • в отношении технических данных и данных о подписке контролёром является Разработчик.

2. Место хранения и порядок передачи данных пациентов

Единственным местом постоянного хранения данных пациентов является локальная база данных Приложения на вашем устройстве. Ни Разработчик, ни привлекаемые им сервисы не создают собственных копий таких данных и не осуществляют их архивное хранение. Порядок резервного копирования, выполняемого операционной системой устройства, отдельно изложен ниже.

При формировании заключения данные обрабатываются в следующем порядке:

  1. Медицинский специалист вводит данные исследования и прикрепляет изображения, после чего они сохраняются в локальной базе данных на устройстве.
  2. При направлении запроса на формирование заключения данные однократно передаются по защищённому каналу связи (HTTPS/TLS) на сервер Разработчика. До отправки изображения уменьшаются и сжимаются; полноразмерные изображения не передаются за пределы устройства.
  3. Сервер Разработчика не сохраняет полученные данные: на их основании он формирует запрос и передаёт его на отдельную GPU-виртуальную машину, находящуюся под контролем Разработчика и предназначенную для работы выбранной модели.
  4. На GPU-виртуальной машине локально запускается модель, которая формирует и возвращает текст заключения. Для выполнения генерации данные не передаются сторонним провайдерам вычислительных ресурсов.
  5. Сформированное заключение возвращается на устройство и сохраняется в локальной базе данных Приложения.
  6. После направления ответа данные запроса не сохраняются на сервере Разработчика или GPU-виртуальной машине и существуют там исключительно в оперативной памяти в течение обработки. Предельное время ожидания ответа от GPU-виртуальной машины составляет 130 секунд, а от запущенного на ней локального движка модели — 120 секунд.

Данные пациентов не записываются в журналы сервера. В частности, журналы не содержат имён, дат рождения, жалоб, описаний исследований, изображений или текстов заключений. В журналах фиксируются исключительно технические метаданные: идентификатор выбранной модели, язык запроса, тип исследования, количество изображений, размер запроса и код ответа.

2.1. Резервное копирование устройства

Локальная база данных Приложения размещается в стандартном хранилище приложения и поэтому включается в резервную копию устройства, если вы активировали резервное копирование в iCloud или на компьютер. Резервное копирование выполняется операционной системой, а не Приложением. Разработчик не имеет доступа к резервным копиям и не может управлять ими.

Резервные копии iCloud защищаются шифрованием Apple, а при включении расширенной защиты данных (Advanced Data Protection) — сквозным шифрованием, ключи которого доступны только вам. Обработка резервных копий регулируется Политикой конфиденциальности Apple.

Если вы не желаете включать данные исследований в резервную копию, отключите резервное копирование Приложения в системных настройках iCloud на устройстве. В этом случае история заключений не будет восстановлена при смене или сбросе устройства.

3. Отправка заключения по электронной почте

При использовании функции отправки заключения по электронной почте текст заключения и адрес получателя передаются на сервер Разработчика и незамедлительно направляются получателю через почтового провайдера. Текст заключения и адрес получателя не сохраняются и не фиксируются в журналах.

После отправки письмо хранится в почтовых ящиках отправителя и получателя и обрабатывается соответствующими почтовыми провайдерами. Такая обработка находится вне контроля Разработчика. Направляя данные пациента по электронной почте, вы несёте ответственность за наличие законных оснований для такой передачи.

4. Обезличивание данных пациента

Для использования Приложения не требуется указывать настоящее имя пациента. Поле «Имя пациента» допускает ввод произвольного текста и используется исключительно для различения исследований в вашем списке. Приложение не сопоставляет введённое значение с какими-либо реестрами и не использует его для иных целей.

Настоятельно рекомендуется указывать псевдоним, инициалы или внутренний номер медицинской карты вместо полного имени пациента. Сокращение объёма идентифицирующих сведений снижает риски для пациента и объём ваших обязанностей, связанных с соблюдением законодательства о персональных данных.

5. Категории обрабатываемых данных

5.1. Данные исследования (вводятся специалистом)

  • Тип ультразвукового исследования (например: щитовидная железа, брюшная полость, эхокардиография, суставы и др.);
  • Снимки УЗИ — фотографии ультразвуковых сканов;
  • Имя или псевдоним пациента — для идентификации исследования в рамках рабочего процесса врача;
  • Пол пациента (мужской/женский);
  • Дата рождения пациента;
  • Рост и вес пациента;
  • Жалобы пациента;
  • Описание исследования — текстовое описание результатов УЗИ;
  • Дополнительные данные — любая дополнительная информация, введённая специалистом.

5.2. Голосовой ввод

При заполнении формы исследования посредством голосового ввода аудиосигнал с микрофона обрабатывается в целях распознавания речи. Аудиозапись не сохраняется в Приложении; сохраняется исключительно распознанный текст.

Распознавание речи. Для голосового заполнения формы используются системные средства распознавания речи Apple. На устройствах под управлением iOS 26 и более поздних версий распознавание полностью выполняется на устройстве, без передачи аудиосигнала. На устройствах с более ранними версиями iOS аудиосигнал с микрофона передаётся на серверы Apple и обрабатывается в соответствии с Политикой конфиденциальности Apple. Если продиктованные данные не должны передаваться за пределы устройства, не используйте голосовой ввод на таких устройствах; все поля могут быть заполнены вручную.

Распределение распознанного текста по отдельным полям формы выполняется локальной моделью, работающей непосредственно на вашем устройстве. Указанная обработка осуществляется автономно: распознанный текст не передаётся за пределы устройства для такого распределения.

5.3. Технические данные

В целях обеспечения защиты и работоспособности сервиса обрабатываются токен подлинности приложения, версии приложения и операционной системы, модель устройства, IP-адрес соединения, а в случае сбоев — отчёт о сбое, включая стек вызовов. Указанные данные не содержат сведений о пациентах.

5.4. Данные о подписке

К данным о подписке относятся статус подписки, идентификатор покупки, анонимный идентификатор пользователя и страна магазина приложений. Платёжные реквизиты не передаются Разработчику и недоступны ему; обработка платежей полностью осуществляется Apple App Store и Google Play.

8. Правовые основания обработки

В отношении пользователей, на которых распространяется GDPR или аналогичное законодательство, применяются следующие правовые основания обработки:

  • Данные пациентов относятся к специальным категориям данных (ст. 9 GDPR). Разработчик обрабатывает их в качестве обработчика по поручению медицинского специалиста. Обязанность обеспечить надлежащее правовое основание — как правило, предусмотренное ст. 9(2)(h) GDPR (медицинская помощь, диагностика) во взаимосвязи со ст. 6(1)(b), (c) или (f), либо явное согласие пациента в соответствии со ст. 9(2)(a) — и проинформировать пациента возлагается на медицинского специалиста как контролёра.
  • Технические данные и защита сервиса — законный интерес (ст. 6(1)(f) GDPR): обеспечение безопасности, работоспособности и предотвращение злоупотреблений.
  • Данные о подписке и адрес электронной почты, указанный вами — исполнение договора (ст. 6(1)(b) GDPR).

9. Сроки хранения

  • Данные пациента на серверах — не хранятся вовсе; существуют только в оперативной памяти на время обработки запроса.
  • Технические логи сервера — содержат метаданные запросов и IP-адреса соединений, не содержат данных пациентов; хранятся не дольше одного года (365 дней), после чего удаляются автоматически.
  • Отчёты о сбоях — по срокам хранения Google Firebase Crashlytics.
  • Данные о подписке — в течение срока действия подписки и последующего периода, установленного провайдером и требованиями бухгалтерского учёта.
  • Локальная база данных на устройстве — бессрочно, пока вы сами не удалите данные (см. раздел 11) или не удалите Приложение.
  • Резервные копии устройства — по правилам и срокам, установленным Apple для резервного копирования; управляются вами в настройках устройства.

Вы вправе получить доступ к своим данным, потребовать их исправления или удаления, ограничения их обработки, возразить против обработки, получить данные в переносимом формате, отозвать ранее предоставленное согласие, а также подать жалобу в надзорный орган по защите персональных данных по месту вашего нахождения.

Удаление данных пациентов осуществляется вами непосредственно в Приложении, поскольку такие данные хранятся только на вашем устройстве:

  • Настройки → Хранилище → Удалить историю заключений — удаляет все сохранённые исследования и заключения;

При удалении Приложения с устройства его локальная база данных также удаляется полностью.

Важно: если у вас включено резервное копирование устройства, копия базы данных может сохраниться в резервной копии и вернуться при восстановлении устройства. Чтобы этого не произошло, отключите резервное копирование для Приложения или удалите резервную копию средствами операционной системы — см. раздел 2.1.

Поскольку Разработчик не располагает копиями данных пациентов, запрос пациента о предоставлении доступа к его данным или об их удалении должен быть направлен медицинскому специалисту, внёсшему соответствующие данные. По вопросам, связанным с техническими данными, отчётами о сбоях и данными о подписке, обращайтесь по адресу doglyadapp@gmail.com. Ответ будет предоставлен в течение 30 дней.

The sole permanent storage location for patient data is the Application's local database on your device. Backups performed by the device's operating system are addressed separately below.

When a report is generated, data is processed as follows:

  1. The medical professional enters examination data and attaches images, which are then stored in the local database on the device.
  2. When a report is requested, the data is transmitted once to the Developer's server over a secure channel (HTTPS/TLS). Images are downscaled and compressed before transmission; full-resolution images are not transmitted from the device.
  3. The Developer's server does not store the data it receives. It prepares a request using that data and forwards the request to a separate GPU virtual machine that is controlled by the Developer and dedicated to operating the selected model.
  4. The model runs locally on the GPU virtual machine, generates the report text, and returns it. Data is not disclosed to third-party compute providers for the purpose of generation.
  5. The generated report is returned to the device and stored in the Application's local database.
  6. After the response is returned, request data is not retained on the Developer's server or the GPU virtual machine and exists there only in memory for the duration of processing. The maximum timeout for a response from the GPU virtual machine is 130 seconds, and the maximum timeout for its local model engine is 120 seconds.

Patient data is not recorded in server logs. In particular, logs do not contain names, dates of birth, complaints, examination descriptions, images, or report text. The logs contain technical metadata only: the selected model identifier, request language, examination type, number of images, request size, and response code.
